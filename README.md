# Справочник СЭДО СФР

[Открыть справочник](https://macros0.github.io/sedo-reference/)

Выберите номер сообщения, контур и редакцию документа. Справочник показывает дерево XML-тегов, поиск по имени, пути и русскому описанию, допустимые значения и ограничения полей.

Источники — [продуктивный](https://lk.sfr.gov.ru/sedo.html) и [тестовый](https://lk-test.fss.ru/sedo.html) каталоги СФР. Полный реестр в [SOURCES.md](SOURCES.md), требования и границы разбора — в [SPEC.md](SPEC.md).

## Новые спецификации через GitHub

Добавьте DOCX в [incoming/prod](incoming/prod) или [incoming/test](incoming/test) и отправьте изменения в main. Скрипт автоматически проверит файлы, добавит версии в справочник, архив DOCX и журнал, затем опубликует GitHub Pages. Подтверждением служит ваш push либо принятие pull request.

Автоимпорт создаёт служебный коммит с обновлёнными данными. Перед следующим локальным push подтяните его командой git pull --ff-only.

Для каждой поставки создавайте отдельную папку, чтобы не смешивать разные версии XSD:

~~~text
incoming/
  prod/
    2026-11-12/
      10110_v3.1.docx
      schemas.zip
  test/
    2026-11-12/
      10110_v3.0.5.docx
      schemas.zip
~~~

Сохраняйте исходные имена СФР с «Тип_сообщения_10110», версией и датой либо используйте короткие имена вроде 10110_v3.1.docx. Номер, версия и дата распознаются из имени; контур определяется папкой prod/test. ZIP необязателен. Без него сохраняется DOCX с пометкой «Схема XSD не загружена». Один ZIP рядом может обслуживать несколько DOCX той же поставки. В ZIP должны быть все импортируемые XSD-зависимости; при нескольких разных подходящих схемах разнесите комплекты по отдельным папкам. ZIP без DOCX не определяет редакцию сообщения.

Повторные запуски не создают дубликатов. Если ZIP пришёл позже, добавьте его рядом с уже загруженным DOCX: появится редакция с деревом тегов. Исправленные файлы можно положить по прежнему пути — изменение содержимого будет обнаружено. Удаление старых файлов из incoming не удаляет сохранённые редакции и оригиналы из справочника.

### Как предложить новые версии через pull request

1. Сделайте fork, создайте ветку и добавьте файлы в incoming/prod/<поставка> или incoming/test/<поставка>.
2. Откройте pull request в main этого проекта. Генерируемые state/data/site редактировать не требуется.
3. Проверка **Validate incoming specifications** выполнит пробный импорт без сохранения и публикации. В Summary и артефакте incoming-validation-report будет отчёт по файлам, определённым версиям и доступным счётчикам сравнения.
4. После проверки и принятия PR владельцем **Publish reference** импортирует набор, сохранит проверенные данные и опубликует сайт. Неуспешный импорт оставляет действующий справочник без изменений; причина указана в Summary и артефакте incoming-import-report.

Проверка PR работает с правами только на чтение и не получает секретов публикации. Запись в основной репозиторий и публикация требуют прав GitHub. Участник без права записи может предложить файлы через PR; самостоятельно изменить общий справочник он не сможет.

Для локальной проверки перед push:

~~~console
python import_inbox.py --check
~~~

Скрипт обрабатывает весь набор во временной папке; при ошибке любого файла изменения набора не сохраняются. Учёт обработанных исходников хранится в state/inbox.json. Результат последнего запуска — inbox-report.json.

### Если имя файла не содержит номер или нужны уточнения

Рядом можно положить необязательный metadata.json с данными по именам DOCX:

~~~json
{
  "spec.docx": {
    "number": "10110",
    "version": "3.1",
    "date": "2026-11-12",
    "source": "СФР, Telegram"
  }
}
~~~

Допустимы number, version, date, source и title. Контур всегда берётся из папки. Для стандартных имён СФР этот файл не нужен.

## Переход типов сообщений на ГИС ЕЦП

Карточки и страницы прежних сообщений показывают соответствующие типы ГИС ЕЦП и быстрые переходы. Помимо типов из [сентябрьского уведомления СФР](https://lk.sfr.gov.ru/sedo.html), добавлены соответствия по модулям ВНиМ/ССВ и возмещений: 10 → 1010, 84 → 8410, 85 → 8510, 104 → 10410, 106 → 10610, 120 → 12010, 121 → 12110, 122 → 12210. Для субсидий добавлены 78 → 7810, 79 → 7910, 82 → 8210 и 83 → 8310, со ссылками на индивидуальные спецификации. У 110 две ветки.

Для 110 показаны две ветки с пояснениями: 11000 — статус выплаты пособия по ВНиМ; 11010 — статус выплаты возмещения расходов страхователю. Выбирать формат нужно по назначению процесса. Названия новых типов берутся из официального перечня; например, 12110 — результат обработки заявления о возмещении.

Прекращение приёма/отправки с 19.09.2026, 10:00 МСК указано только для десяти прежних типов из сентябрьского уведомления и относится к продуктивному контуру. Остальным соответствиям эта дата не присваивается. Наличие прежнего типа в каталоге само по себе не подтверждает его приём шлюзом.

Новый тип открывается отдельно, со своими версиями и XSD: при переходе менялась структура XML. Прежние сообщения остаются доступны для изучения. В data/message-transitions.json хранятся явные соответствия, назначения и источники: уведомление СФР, «Приложение 10. ВНиМ, ССВ. Том 1» v3.3 и «Приложение 6. Возмещения. Том 1» v3.0. Дата отключения привязана к конкретному источнику. Совпадение по правилу «дописать 10» само по себе не создаёт переход. Для 32–34 и типов, сохранивших номер (например, 125), замена не выдумывается. Ссылки показываются только на типы, имеющиеся в выбранном контуре.

## Типы из отдельных спецификаций модулей

Общий перечень СФР может отставать от модульных DOCX. При каждом автоматическом обновлении скрипт дополнительно читает заголовки разделов «Тип сообщения N: …» в спецификациях приложений. Если номер отсутствует в общем перечне этого контура, создаётся запись с названием, модулем, версией, датой и ссылкой на документ. Оглавление, упоминания в тексте и XML-примеры не используются как самостоятельные объявления типов. Строки общего перечня имеют приоритет; контуры обрабатываются раздельно.

Так добавлены 600–602 для продуктивного контура и 611–612 для обоих контуров. Оригинальные DOCX модулей сохраняются по хешу и доступны для скачивания, включая прежние документы после их удаления у СФР. Записи дополнений сохраняются в истории каталога. При найденной и проверенной XSD создаётся редакция с деревом. Один заголовок DOCX без схемы даёт только запись в каталоге.

В отчёте автоматического обновления new_messages перечисляет новые номера по контурам; new_revisions по-прежнему относится к редакциям с деревом или отдельно импортированным DOCX. Данные типов хранятся в снимках state/snapshots, дополнительная ручная таблица номеров не требуется.

## Схемы внутри модульных DOCX и на связанных страницах

Автообновление читает не только ZIP из /specs_sedo/. Если основная страница ссылается на /prab.html, сборщик обходит эту страницу в том же контуре и загружает опубликованные там ZIP из /prab/. Это источник полной XSD карточки застрахованного лица (86, 87, 88); в DOCX РПУ v1.12 дана ссылка на эту страницу, а не OLE-вложение.

Из модульных DOCX извлекаются OLE Native Package и вложенные XSD, ZIP и 7z. Вложения читаются как данные в память, без запуска Word/OLE; размер проверяется до распаковки, действуют ограничения на число и суммарный объём файлов. Для построения используется точный XSD: номер связывается с корнем из таблицы структуры своего раздела; проверяются пространство имён, все импорты и ограничения существующим разборщиком. Контуры и редакции изолированы. Временные копии XSD редактора объединяются только при совпадении полного нормализованного XML-контракта, включая пространства имён и зависимости; разные структуры требуют проверки.

Исходный DOCX сохраняется целиком. Извлечённые XSD без изменения содержимого складываются в воспроизводимый ZIP; хеши, путь OLE-вложения и имя исходного архива записываются в снимок. Новая версия документа или схемы образует отдельную редакцию, прежние деревья и события журнала сохраняются. В отчёте schema_diagnostics перечисляются нераспознанные вложения, отсутствующие зависимости и другие причины, по которым дерево построить нельзя; неполная схема не выдаётся за готовую.

## Разделы и сравнение прежних форматов

Меню разделов строится по вложенным блокам текущего XML. Выбор блока показывает его дерево и ограничивает поиск его полями; переход к дочернему полю сохраняет выбранный раздел. Для возврата ко всему сообщению выберите «Все разделы» или «Сбросить».

На страницах связанных типов доступны ссылки «Сравнить 105 → 10510» и обратное направление. Выбор редакций показывает номер сообщения и контур. Кнопка «Поменять местами» меняет направление сравнения; ссылки на поля открывают правильный тип каждой стороны. Разрешены редакции одного типа и явно подтверждённые соответствия из data/message-transitions.json. При смене имени корня полные XML-пути также меняются.

Диагностика недостающих деревьев сохраняется в data/schema-coverage.json. Сборщик извлекает полные схемы из текста DOCX, обходит опубликованные страницы МЧД/ЭЛН и восстанавливает неверные относительные пути только при однозначном соответствии имени и пространства имён внутри исходного архива. Группы атрибутов и альтернативы union отображаются с исходными ограничениями; правила разных альтернатив не смешиваются.

## Локальный просмотр

Скачайте репозиторий и откройте site/index.html в браузере. Для просмотра не требуется интернет.

## Сборка

Для сборки: Python 3.10+, Node.js 18+ и зависимости из requirements.txt (olefile и py7zr для OLE/7z-вложений). Для просмотра готовой папки site нужен только браузер.

~~~console
python -m pip install -r requirements.txt
python update_catalog.py --offline
python verify.py
python build_site.py
~~~

Для проверки свежих материалов СФР запустите первую команду без --offline. Проверьте отчёт и новые редакции перед включением данных в публичный выпуск.

## Публикация

При изменениях ветки main GitHub Actions проверяет данные, собирает папку site и публикует её через GitHub Pages. Ручной процесс Check SFR catalogs собирает кандидат обновления источников для проверки.

Приложение использует относительные пути и поддерживает размещение в подпапке репозитория. Адрес выбранной редакции и поля можно передать ссылкой.

## Автоматическое обновление

GitHub Actions проверяет продуктивный и тестовый каталоги ежедневно в 07:17 по Москве (04:17 UTC). Можно запустить Check SFR catalogs вручную.

Обновление сначала собирается во временной папке. После загрузки обоих контуров проверяются сопоставления схем, деревья всех редакций и сохранность старых полей. Новые редакции добавляются в историю, исчезнувшие ссылки отмечаются как архивные. При одинаковых исходниках дубликаты редакций не создаются.

Успешный запуск сохраняет данные, исходные DOCX всех редакций, ZIP со схемами и снимки каталогов в Git, фиксирует время проверки и явно запускает Publish reference. Публичный сайт показывает время последней успешной проверки. При ошибке загрузки или разбора действующий справочник сохраняется; отчёт доступен в Summary и артефакте sfr-update-report соответствующего запуска Actions. Следующий запуск повторит проверку. Уведомления о сбоях доставляются согласно настройкам уведомлений вашего GitHub.

История начинается с сохраненного среза 12.11.2026. Версии, удалённые СФР до первого сохранения, автоматически восстановить нельзя. Новые конструкции XSD или неоднозначные сопоставления могут потребовать изменения сборщика.

Для автоматического обновления локально выполните python auto_update.py из корня проекта. Изменения публикуются отдельным коммитом. Расписание GitHub Actions может запускаться с задержкой.

## Оригиналы DOCX

«Скачать DOCX» в карточке редакции, открытом дереве и сравнении загружает исходный документ из нашего архива. Документ доступен локально и на GitHub Pages, даже если СФР удалит или заменит файл по прежней ссылке. Отдельная ссылка на сайт СФР сохранена.

Оригинальные байты хранятся в state/objects/<SHA256>, публичная копия — в site/documents/<SHA256>.docx. Одинаковые DOCX имеют один адрес скачивания, даже если относятся к нескольким редакциям схемы. При сборке проверяются SHA256 и читаемость DOCX; отсутствующий или повреждённый оригинал останавливает автоматическое обновление до публикации. Новая редакция добавляет свой оригинал; ранее сохранённые документы не удаляются. Восстановлены все 56 оригиналов текущих редакций из исходного локального архива с проверкой ранее записанных контрольных сумм.

Сборка не скачивает документы: для повторной сборки достаточно файлов репозитория. Проверки сохранности оригиналов входят в python -m unittest discover -s tests -v.

## Сравнение редакций

На странице сообщения нажмите «Сравнить редакции». В полях «Было» и «Стало» независимо выбираются любые сохраненные редакции одного номера, включая пару продуктив/тест. В открытом дереве также доступна ссылка «Сравнить с другой редакцией».

Сравнение показывает добавленные и удаленные XML-пути, изменения типа, обязательности, кратности, групп выбора, пространств имен, фиксированных значений, ограничений длины и диапазона, шаблонов, перечней значений и описаний. Для изменений есть таблица «Было/Стало», фильтр категории, поиск и ссылки на поля обоих деревьев. Можно поменять стороны местами и передать адрес сравнения ссылкой.

Сравнение использует нормализованные данные XSD. Порядок перечисления допустимых значений и технические имена файлов на результат не влияют. Для перемещенного тега показываются удаление прежнего пути и добавление нового. Произвольный текст Word сравнивается в рамках отдельно извлеченных описаний XSD. Неоднозначный повторяющийся XML-путь приводит к сообщению о невозможности сравнения.

Дополнительная проверка перед публикацией: node tests/test_compare.cjs. Данные для сравнения загружаются отдельно для двух выбранных редакций и работают локально через file://.

## Журнал обновлений

[Открыть журнал](https://macros0.github.io/sedo-reference/#updates=1) можно по ссылке в шапке. На странице номера сообщения есть «Журнал сообщения». Доступны поиск по номеру, названию и версии и фильтр продуктивного/тестового контура. Ввод полного существующего номера показывает только это сообщение, даже если номер упоминается в названии другого сообщения. Состояние фильтров сохраняется в адресе страницы.

В журнале показано время первого успешного обнаружения каждой редакции в справочнике по Москве; дата документа СФР отображается отдельно. Начальные 56 редакций отмечены «Первичное наполнение» с датой первого сбора 12.11.2026, 15:38 МСК. Это не дата публикации документов СФР. Для каждой записи доступны дерево, архивный DOCX и сравнение с ранее обнаруженной редакцией того же номера и контура. Если предыдущей редакции нет, предлагается сравнение с доступным другим контуром.

Время первого успешного получения снимка хранится в state/observations.json. Журнал в data/catalog.json восстанавливается из истории снимков: повторные проверки, исчезновение и возврат прежнего файла новых событий не создают. Изменение DOCX или используемой XSD создаёт отдельную редакцию даже при прежнем номере версии. События сохраняются вместе с историями редакций; неуспешное автоматическое обновление не меняет опубликованный журнал. Если дата старого снимка неизвестна, она показана как несохранённая.

В каждой записи сразу показано число добавленных, удалённых и изменённых XML-полей. Рядом указано направление сравнения. Для новой редакции сравниваются предыдущая сохранённая редакция того же контура и новая; если предыдущей нет, за основу берётся доступный другой контур. В этом случае счётчики показывают изменения от другого контура к редакции записи. Когда сравнивать не с чем, выводится пояснение вместо нулевых счётчиков.

Сводки рассчитываются при сборке через summarize_updates.cjs тем же движком web/compare-core.js, что и полное сравнение. Изменённый XML-путь учитывается один раз, даже если изменилось несколько его свойств. Сведения о появлении редакций остаются неизменными; сводки добавляются только в публикуемый каталог. Дополнительная проверка: node tests/test_update_summaries.cjs.

Ссылки на JS, CSS и каталог в собранном index.html содержат версию содержимого, чтобы кэш старых скриптов не мешал новой навигации и обновлённым данным.

Фильтр «Только с изменениями» оставляет записи, у которых хотя бы один рассчитанный счётчик больше нуля. Он работает вместе с поиском и выбором контура; состояние сохраняется в ссылке через changed=1. По умолчанию фильтр выключен. Записи без готового сравнения при включённом фильтре скрыты.

«Период обнаружения» фильтрует по дате появления редакции в справочнике, а не по дате документа СФР. Неделя — последние 7 календарных дней, месяц — последние 30, включая сегодня по Москве. В выбранном периоде доступны даты «С»/«По», обе границы включены; одну из них можно оставить пустой. При неверном порядке дат показана ошибка. По умолчанию доступна вся история; записи с неизвестной датой скрыты при активном фильтре дат. Период работает вместе с остальными фильтрами и сохраняется в ссылке: period=week/month/custom, from/to в формате YYYY-MM-DD. Проверка границ дней и часового пояса: node tests/test_journal_dates.cjs.

«Сбросить фильтры» очищает поиск, контур, выбранный период и даты, выключает «Только с изменениями» и возвращает полный журнал. Параметры фильтров удаляются из ссылки; остаётся #updates=1.

### Excel для сопоставления форматов

На странице сравнения выберите «Было» и «Стало», затем нажмите **«Выгрузить Excel для сопоставления»**. Поддерживаются две редакции одного сообщения, разные контуры и связанные прежний/новый типы в обоих направлениях. Выгружается вся пара независимо от экранного поиска и фильтров.

В книге есть листы **Сопоставление**, **Было**, **Стало**, **Изменения** и **О выгрузке**. В жёлтых ячейках укажите новый полный XML-путь, решение и комментарий. Описание и ограничения выбранного нового поля подтянутся формулами Excel. Новый путь можно скопировать с листа «Стало» или выбрать из списка. Совпадающие полные пути заполнены заранее со статусом «Не проверено»; переименованные пути связываются человеком после проверки смысла, вложенных полей и ограничений.

При разделении поля на несколько новых дублируйте строку; при объединении допустим одинаковый новый путь в нескольких строках. Исходные деревья содержат полные записи полей, ограничения, значения и альтернативы union. На последнем листе сохранены номера сообщений, контуры, редакции, идентификаторы и ссылки на источники и архивные DOCX. Длинный текст можно прочитать в строке формул или увеличив высоту строки.

Работу сохраняйте в скачанной книге: повторная выгрузка создаёт новый файл. Заполненную книгу можно загрузить обратно в браузере, как описано ниже. Файл формируется в браузере; локальная копия ExcelJS с лицензией находится в web/vendor и загружается только при нажатии кнопки.

### Обратная загрузка ручных соответствий

1. В скачанном Excel на листе **Сопоставление** заполните путь «Стало» и установите решение **«Подтверждено»**. Комментарий необязателен.
2. На сравнении тех же редакций нажмите **«Загрузить сопоставления из Excel»** и выберите сохранённую книгу.
3. Проверьте предпросмотр и нажмите **«Применить сопоставления»**. При ошибках идентификаторов редакций или путей исправьте книгу: неполный набор с ошибками не применяется.

Для подтверждённых пар сравниваются типы, кратность, допустимые значения, ограничения, альтернативы union и описания из исходных деревьев справочника. Редактирование описаний и ограничений в Excel не меняет данные сравнения. Сопоставленные пути исключаются из отдельных удалений/добавлений; пары без различий доступны через фильтр **«Сопоставлено без изменений»**. Заполненные пары со статусами «Не проверено» и «Переработано» показаны в предпросмотре как отдельные предложения «Из Excel — не подтверждено»: их можно подтвердить прямо в браузере. Строки «Требует уточнения» предложены без отметки по умолчанию; «Удалено» не превращается в предложение Excel. Пустой новый путь не применяется. Некорректные неподтверждённые пути отмечены предупреждениями; ошибочные подтверждённые строки блокируют применение.

В предпросмотре есть **поиск по тегу, пути, описанию и комментарию** с обеих сторон и фильтр **«Только предложенные»**. Поиск не учитывает регистр и различие е/ё. Фильтры сбрасывают номер страницы, сохраняют отметки и не ограничивают применение: используются все отмеченные пары, в том числе скрытые поиском. Кнопки выбора всех предложений действуют на весь набор. Уже сохранённые пары можно открыть кнопкой «Просмотреть сопоставления».

При разделении или объединении полей указывайте несколько подтверждённых строк. Для сопоставленных родительских блоков справочник автоматически предлагает вложенные поля с одинаковыми полными относительными путями. В предпросмотре они отмечены как «По относительному пути»: видны родительская пара, относительный путь и описания обоих полей. Предложения выбраны заранее; можно исключить отдельные пары, снять или выбрать все. До нажатия «Применить сопоставления» они не сохраняются. Весь список доступен постранично. Ручные строки имеют приоритет, для вложенных блоков учитывается ближайшая ручная пара с обеих сторон. Занятые и неоднозначные пары при разделении/объединении показаны в разделе «Требуют ручного решения»; их нужно уточнить в Excel. Поля с разными относительными путями автоматически не связываются. Для ранее сохранённых родителей есть кнопка «Предпросмотр вложенных тегов». При повторной выгрузке все применённые пары и комментарии сохраняются в новой книге.

Файл читается только в браузере и не отправляется на сервер или GitHub. Соответствия сохраняются в localStorage для **точной пары редакций** и работают также при перестановке «Было»/«Стало». Для новых редакций нужен отдельный набор. Другие посетители их не видят. Кнопка **«Сбросить сопоставления»** возвращает обычное сравнение. Если браузер запрещает хранение, набор действует в текущем сеансе; сохраните Excel для повторной загрузки. Очистка данных сайта удалит сохранённые пары.

Поддерживается XLSX из справочника размером до 10 МиБ с заявленным распакованным объёмом до 64 МиБ. Формулы в значимых полях соответствий не принимаются; вычисляемые столбцы описаний/ограничений не читаются. Уже скачанные книги с листами «Сопоставление» и «О выгрузке» также подходят.

### Зависимости XSD через WSDL

Автоматический сбор WSDL из российской сети и публикация через отдельный токен владельца описаны в [инструкции сборщика](docs/russian-collector.md). При наличии сохранённых серверных снимков GitHub проверяет их офлайн и использует для обновления; прямой доступ к WSDL из GitHub не требуется.

Автообновление читает опубликованные ссылки WSDL шлюзов СФР и проходит их импорты WSDL/XSD. Полученные библиотеки дополняют неполные схемы модульных DOCX, включая служебные типы Приложения 2. Полные исходные пакеты сохраняют приоритет.

Продуктивный и тестовый контуры используют отдельные списки официальных шлюзов. Ссылка на тестовый шлюз со страницы продуктивного контура не делает его схемы продуктивными. Схемы не исправляются подстановками имён: например, RegNumSfr и regNumSFR могут иметь разные ограничения. Обход ограничен HTTPS, адресом шлюза, количеством и размером файлов.

В state/objects сохраняются оригинальные WSDL, XSD и DOCX; в снимке указаны URL, SHA-256 и состав сформированного архива зависимостей. Изменение зависимостей создаёт отдельную редакцию, прежние редакции остаются в истории. При недоступности WSDL сохраняется последний успешный комплект того же контура. Если такого комплекта ещё нет, деревья по неподтверждённым зависимостям не публикуются. Причина отражается в update-report.json и data/schema-coverage.json.

Для проверки доступности опубликованных WSDL без изменения справочника: `python wsdl_sources.py --probe`. Такая же проверка выполняется на GitHub перед публикацией Pages; результат виден в Summary запуска. Недоступность внешнего шлюза фиксируется в отчёте и не мешает публикации уже проверенных редакций.

### Редактирование соответствий в браузере

Excel необязателен: на странице сравнения нажмите **«Добавить соответствие»** либо **«Просмотреть сопоставления»**. В таблице доступны **«Изменить»**, **«Убрать»** и отметка применения каждой пары, включая уже подтверждённые.

В форме выберите теги «Было» и «Стало» из нужных схем. Поиск по пути или описанию сокращает список; сам текст поиска не меняет выбранный тег. При одном найденном теге Enter выбирает его. Комментарий можно изменить там же. **«Сохранить пару в черновик»** возвращает в предпросмотр; изменения ещё не сохраняются в браузере и не меняют результат сравнения.

Жёлтая полоса показывает, что черновик не применён, сколько пар сохранено и сколько выбрано. Она остаётся видна при прокрутке к результатам. Нажмите **«Применить и обновить сравнение»**: приложение сохранит весь отмеченный набор, обновит результаты без перезагрузки и покажет подтверждение у счётчиков. Во время незавершённой правки строки применение недоступно. **«Отменить предпросмотр»** оставляет прежний сохранённый набор.

Дубликат одной и той же выбранной пары и несуществующий тег не принимаются. Разделение и объединение полей остаются допустимыми. При изменении родительского блока пересчитываются непроверенные относительные предложения; явные ручные дочерние пары не переносятся автоматически. Убранная связь не восстанавливается автоматически внутри текущего черновика. Правки и отметки сохраняются при поиске, фильтрации и переходе между страницами. Применённые браузерные изменения включаются в следующую выгрузку Excel; исходный файл и схемы не редактируются.
