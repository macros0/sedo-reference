# Сборщик WSDL в российской сети

Контейнер Proxmox 102 загружает WSDL и все зависимости XSD отдельно для продуктивного и тестового контуров. Он обращается к опубликованным официальным адресам по HTTPS, проверяет сертификаты и сохраняет исходные байты без исправлений схем. Нужны только Python 3.9+ и исходящие соединения HTTPS; Git, Docker и дополнительные пакеты Python не требуются.

## Обмен с GitHub

`collector.py` отправляет данные через GitHub Git Data API в `macros0/sedo-reference` от аккаунта владельца отдельного токена. Один атомарный коммит добавляет объекты `state/objects/<SHA-256>` и манифесты `state/collector/<prod|test>/<content_id>.json`. При неизменных данных нового коммита нет; прежние снимки остаются. При конкурентном изменении main сборщик повторяет попытку поверх новой вершины, без force push. При отказе одного контура успешный второй комплект сохраняется, а запуск завершается ошибкой для наблюдения через systemd.

GitHub Actions повторно вычисляет SHA-256 каждого входа и воспроизводит обход WSDL полностью офлайн. Проверяются контур, адреса импортов, пространства имён, ограничения размеров и совпадение восстановленного ZIP и метаданных. Только после этого строится новая редакция. Существующие редакции и исходные DOCX сохраняются. При наличии серверного снимка обновление использует его; прямой доступ GitHub к WSDL не требуется. Доступность шлюзов с GitHub отдельно фиксируется диагностикой и не блокирует проверенные снимки.

## Установка

В `/opt/sedo-collector` разместите `collector.py`, `collector_snapshots.py`, `sync.py`, `wsdl_sources.py` и каталог `certs`. Исходники принадлежат root и недоступны для записи сервису. Создайте отдельного системного пользователя `sedo-collector` без входа в оболочку. Unit-файлы из `deploy/` разместите в `/etc/systemd/system/`.

В настройках GitHub создайте **fine-grained personal access token**: Resource owner — ваш аккаунт, **Only select repositories → sedo-reference**, **Contents → Read and write**, стандартный Metadata read-only. Остальные разрешения не нужны. Рекомендуемый срок — 90 дней; GitHub предупредит владельца об истечении. Токен хранится только в `/etc/sedo-collector/github-token`, владелец root, группа sedo-collector, права 0640, родительский каталог 0750. Не добавляйте его в репозиторий, аргументы команд или отчёты.

```sh
systemctl daemon-reload
systemctl start sedo-collector.service
systemctl enable --now sedo-collector.timer
systemctl list-timers sedo-collector.timer
journalctl -u sedo-collector.service -n 30 --no-pager
```

Расписание — ежедневно в 07:00 по Москве с задержкой до двух минут; существующая проверка каталога на GitHub запускается в 07:17. Публикация нового серверного снимка также запускает Pages через обычное событие push. Если сервер был выключен, Persistent запускает пропущенную проверку после включения.

Для безопасного пробного сбора без токена и публикации: `python collector.py --capture-to /tmp/sedo-capture`. Для одного контура добавьте `--environment prod` или `--environment test`.

## Что защищает токен

Токен подтверждает право его владельца изменять этот репозиторий; он не привязан к физическому серверу или IP. Доступ Contents write разрешает изменение содержимого репозитория, а ограничение скрипта только путями снимков — правило самого сборщика. Отдельной криптографической подписи сервера в этой схеме нет. При компрометации сервера отзовите токен в GitHub, проверьте коммиты и выдайте новый. Разрешения других репозиториев, управления аккаунтом и изменения workflow этому токену не выдаются.

Для замены токена остановите сервис, атомарно обновите файл с сохранением владельца и прав, затем выполните разовый запуск и проверьте журнал. Остановка автоматического сбора: `systemctl disable --now sedo-collector.timer`. Она не удаляет сохранённые снимки или опубликованные редакции.
