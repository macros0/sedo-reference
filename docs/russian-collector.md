# Сборщик WSDL в российской сети

Контейнер Proxmox 102 загружает WSDL и все зависимости XSD отдельно для продуктивного и тестового контуров. Он обращается к опубликованным официальным адресам по HTTPS, проверяет сертификаты и сохраняет исходные байты без исправлений схем. Нужны только Python 3.9+ и исходящие соединения HTTPS; Git, Docker и дополнительные пакеты Python не требуются.

## Обмен с GitHub

`collector.py` отправляет данные через GitHub Git Data API в `macros0/sedo-reference` от аккаунта владельца отдельного токена. Один атомарный коммит добавляет объекты `state/objects/<SHA-256>` и манифесты `state/collector/<prod|test>/<content_id>.json`. В том же коммите файл `state/collector/<prod|test>/current.json` хранит ID подтверждённого манифеста и время начала его захвата. При конфликте записи сборщик повторяет проверку на новой вершине Git. Захват, начатый раньше, сохраняет исторический комплект, даже если более поздний захват уже продвинул указатель. Если СФР вернулся к прежнему набору при новом захвате, указатель снова выберет этот набор. Более поздний захват тех же байтов обновляет время в `current.json`. При повторной записи одного наблюдения с уже сохранёнными входами новый коммит не создаётся.

При конкурентном изменении main сборщик повторяет попытку поверх новой вершины без force push. При отказе одного контура успешный второй комплект сохраняется, а запуск завершается ошибкой для наблюдения через systemd.

GitHub Actions повторно вычисляет SHA-256 каждого входа и воспроизводит обход WSDL полностью офлайн. Проверяются контур, адреса импортов, пространства имён, ограничения размеров и совпадение восстановленного ZIP и метаданных. Существующие редакции и исходные DOCX сохраняются. При наличии серверного снимка обновление использует его. Текущую доступность шлюзов из сети запуска показывает команда `python wsdl_sources.py --probe`.

## Установка

В `/opt/sedo-collector` разместите `collector.py`, `collector_snapshots.py`, `collector_feed.py`, `collector_transport.py`, `state_lock.py`, `sync.py`, `wsdl_sources.py`, `schema.py` и каталог `certs`. Исходники принадлежат root и недоступны для записи сервису. Создайте отдельного системного пользователя `sedo-collector` без входа в оболочку. Unit-файлы из `deploy/` разместите в `/etc/systemd/system/`.

В настройках GitHub создайте **fine-grained personal access token**: Resource owner — ваш аккаунт, **Only select repositories → sedo-reference**, **Contents → Read and write**, стандартный Metadata read-only. Остальные разрешения не нужны. Рекомендуемый срок — 90 дней; GitHub предупредит владельца об истечении. Токен хранится только в `/etc/sedo-collector/github-token`, владелец root, группа sedo-collector, права 0640, родительский каталог 0750. Не добавляйте его в репозиторий, аргументы команд или отчёты.

```sh
systemctl daemon-reload
systemctl start sedo-collector.service
systemctl enable --now sedo-collector.timer
systemctl list-timers sedo-collector.timer
journalctl -u sedo-collector.service -n 30 --no-pager
```

Расписание — ежедневно в 07:00 по Москве с задержкой до двух минут; существующая проверка каталога на GitHub запускается в 07:17. Публикация нового серверного снимка также запускает Pages через обычное событие push. Если сервер был выключен, Persistent запускает пропущенную проверку после включения.

Для безопасного пробного сбора без токена и публикации: `python collector.py --capture-to /tmp/sedo-capture`. Для одного контура добавьте `--environment prod` или `--environment test`.

## Локальный захват и восстановление Home

Указывайте одну папку входов в `collector.py --capture-to <входы>` и `update_catalog.py --state <входы> --out <выходы>`. Используйте любой путь входов. Если другая операция удерживает `.update.lock`, дождитесь её окончания и повторите захват. Если прервалась установка каталога, сначала повторите обновление с исходными аргументами. Файл блокировки сохраняется между запусками, сама блокировка снимается при выходе процесса.

Home записывает `.pending-at` перед установкой первого объекта и добавляет квитанцию `.observed-at` после объектов и манифеста. Затем сборщик атомарно заменяет `current.json`. При прерывании до замены активен прежний подтверждённый комплект. При прерывании после замены доступен новый комплект с квитанцией. Повторный захват тех же байтов использует прежнюю дату квитанции, а актуальность указателя определяется временем начала нового захвата. В режиме SourceCraft незавершённый комплект Home требует подтверждённого фида для чтения библиотеки.

### Переход на единый указатель

Остановите старый таймер и дождитесь завершения запущенных захватов. Обновите сборщик и код чтения в справочнике, затем выполните новый захват обоих контуров. До появления `current.json` справочник читает прежний `current` с ID, а сборщик учитывает доступную старую отметку `current-observed-at` при проверке порядка. После перехода оба используют `current.json`. История первого наблюдения остаётся в квитанциях. Старые бинарники не видят новый указатель, поэтому для возобновления таймера нужен обновлённый сборщик. Проверьте `content_id` и `capture_started_at` отдельно для prod и test.

Перед переходом сборщик проверяет манифест и объекты из старого `current`. Дату первого наблюдения он берёт из квитанции Home, журнала `sources.home` или из проверенного старого манифеста, когда для этого ID отсутствуют данные SourceCraft. Квитанция сохраняется и при повторном захвате тех же байтов, и при переходе на другой ID. `current-observed-at` задаёт нижнюю границу времени для продвижения указателя. Если замена `current.json` прервалась, чтение продолжится по старому указателю. Повторите захват после устранения причины прерывания.

Если ID общий для Home и SourceCraft и дата первого наблюдения Home неизвестна, сборщик остановит миграцию с контуром, ID и путём квитанции. Оставьте таймеры остановленными и найдите подтверждённую дату в резервной копии квитанции, архиве прежних манифестов Home или журнале захвата Home. В локальной папке входов восстановите `collector/<контур>/home/<ID>.observed-at` одной строкой ISO 8601 с часовым поясом и переводом строки. Для сборщика с Git Data API восстановите тот же файл под `state/` в `main` через обычную процедуру изменения репозитория. Повторите захват, когда файл доступен сборщику. Пока дату подтвердить не удалось, доступен старый указатель.

Если прежняя версия Home оставила квитанцию без манифеста, диагностика укажет контур, ID и путь манифеста. Начните с повторного захвата нужного контура в ту же папку. Если вернутся те же байты, Home восстановит манифест и использует дату из квитанции. Если возвращается другой ID и исходных байтов нет, изолируйте остаток следующим образом.

1. Приостановите захват, обновление и импорт для этой папки. Проверьте, что `collector/<контур>/<ID>.json` отсутствует. Активный ID указан в `current.json`, для старой установки проверьте `current`. Если существует `collector/processed.json`, проверьте, что в `sources.home.<контур>` нет записи для этого ID. Если на ID ссылается указатель или журнал Home, восстановите подтверждённый комплект из резервной копии.
2. Сохраните точную копию `collector/<контур>/home/<ID>.observed-at` вне папки входов. Переместите оригинал в `collector/<контур>/home/orphans/<ID>.observed-at` с прежним именем и содержимым. Если туда уже записана другая квитанция с этим ID, остановитесь и проверьте происхождение обеих. Объекты, квитанции SourceCraft, журнал и указатели оставьте на месте.
3. Возобновите захват и обновление. История Home продолжит читаться. Если комплект с тем же ID появится вновь, Home восстановит квитанцию из сохранённых байтов и вернёт наблюдение в историю с прежней датой.

## Что защищает токен

Токен подтверждает право его владельца изменять этот репозиторий; он не привязан к физическому серверу или IP. Доступ Contents write разрешает изменение содержимого репозитория, а ограничение скрипта только путями снимков — правило самого сборщика. Отдельной криптографической подписи сервера в этой схеме нет. При компрометации сервера отзовите токен в GitHub, проверьте коммиты и выдайте новый. Разрешения других репозиториев, управления аккаунтом и изменения workflow этому токену не выдаются.

Для замены токена остановите сервис, атомарно обновите файл с сохранением владельца и прав, затем выполните разовый запуск и проверьте журнал. Остановка автоматического сбора: `systemctl disable --now sedo-collector.timer`. Она не удаляет сохранённые снимки или опубликованные редакции.
