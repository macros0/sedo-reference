# Исправление №14: значения xs:date и xs:duration

17 ноября 2026. Изменены только `web/compare-core.js`, `tests/test_compare.cjs` и `tests/test_update_summaries.cjs`; этот отчёт описывает блок №14 общего плана. Уже внесённая другим исполнителем нормализация кратности №15 сохранена. Сравнение с `fix20r-baseline.tmp/original.zip` подтвердило состав изменений в этих трёх файлах.

## Причина и исправление

Общий движок сравнения нормализовал `dateTime`, но возвращал лексическое написание `date` и `duration` без типизированного преобразования. Поэтому ограничения с тем же значением считались изменившимися.

- `date` приводится к полуночи с общей календарной арифметикой `dateTime`. `Z`, `+00:00` и `-00:00` эквивалентны. Смещения, переходящие на соседнюю дату, обрабатываются; отсутствие зоны остаётся отдельным значением.
- `duration` приводится к двум независимым компонентам: числу месяцев и числу секунд с исходной точностью дробной части. `P1Y` равно `P12M`, `P1D` равно `PT24H`; `P1M` и `P30D` различаются. Целые компоненты используют `BigInt`, дробная часть сохраняется строкой. Отрицательный ноль приводится к нулю. Некорректные формы без компонентов, с пустым `T` и с запрещённым плюсом остаются лексическими значениями.
- Нормализация применяется через существующий путь фиксированных значений, значений по умолчанию, перечислений, границ и ограничений ветвей union. Исходное написание остаётся доступно для отображения.

В общем календарном помощнике исправлена арифметика отрицательных годов: високосность проверяется по исходному году; число завершённых лет считается без года ноль, с делением `BigInt` к нулю для отрицательного счётчика. Это устраняет отказ на `-0004-02-29` и предотвращает совпадение соседних дат `-0004-12-31` и `-0003-01-01`.

Опора для календарных правил: [XSD 1.0, §3.2.7](https://www.w3.org/TR/xmlschema-2/#dateTime) исключает год ноль; [приложение E](https://www.w3.org/TR/xmlschema-2/#adding-durations-to-dateTimes) задаёт високосность через делимость исходного года на 4, 100 и 400.

## Проверка

Перед исправлением оба целевых набора завершились с кодом 1: сравнение показало ложные изменения `flags`, `facets` и `values` для `2026-11-17Z` / `2026-11-17+00:00`; журнал получил `changed: 1` вместо нуля. После первоначальной реализации дополнительная проверка отрицательной високосной даты также дала ожидаемый отказ, после исправления календарного помощника — успех.

Итоговые команды прошли с кодом 0:

```text
node tests/test_compare.cjs
node tests/test_update_summaries.cjs
```

Регрессии покрывают нулевые часовые пояса, отсутствие зоны, переход календарной даты и эры, отрицательные годы и год ноль, годы за пределами четырёх цифр, годы/месяцы и дни/часы длительности, отрицательные компоненты и ноль, числа больше безопасного диапазона `Number`, произвольную дробную точность, некорректные формы и различия настоящих значений. Счётчики журнала отдельно проверены для обеих пар из ревью и для `P1D` / `PT24H`.

Локальный lxml подтвердил исходные пары, нулевую длительность, `PT.5S` / `PT0.5S`, `PT1.S` / `PT1S`, различие месяца и 30 дней, а также смещения у отрицательных дат. При контрольном сравнении он неожиданно принял `-0003-01-01Z` в перечислении, ограниченном `-0004-12-31Z`. Поэтому этот результат lxml не использован как эталон: явная регрессия сохраняет разные соседние календарные даты, а арифметика следует правилам XSD 1.0, указанным выше.

Сборка, полные наборы, генерируемые файлы, коммит и публикация в этом блоке не выполнялись.
