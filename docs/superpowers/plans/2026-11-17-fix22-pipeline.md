# Сбор источников, локальное обновление и проверка PR

17 ноября 2026 года. Выполнены замечания №1–5, 7 и 8 из [плана ревью](2026-11-17-full-review-and-fixes.md). Изменения №6, 9 и 10 проверяются в части XSD совместно с другими исправлениями.

## Поведение

- **№1.** Локальное обновление строит инвентарь, каталог и поля во временной папке, проверяет все статусы и только затем записывает изменения. Блокировки охватывают конкретные `--state` и `--out`, в том числе в разных родительских каталогах. Журнал хранит предыдущие байты изменяемых файлов до подтверждения установки. Отказ перед установкой, ошибка при замене и прерывание очистки проверены отдельно. Остальные файлы в обоих каталогах сохраняются. Прямой сбор, прерванный в произвольном `--state`, восстанавливается перед копированием его входов.
- **№1, восстановление старых данных.** При экспорте исторический индивидуальный DOCX без однозначной XSD остаётся источником документа. Для ранее сопоставленного архива, дерево которого не удалось построить, миграция требует прежнюю редакцию в каталоге, статус `review` в предыдущем индексе полей и отсутствие прежнего готового файла дерева. Она сохраняет причину и соответствие редакции конкретным архивным снимкам. Новый отказ у прежде готовой редакции по-прежнему останавливает сборку. В проверке с последовательностью A → R → B после исключения недопущенной R у готовой B меняется ссылка сравнения с R на A. Сохраняются ID обеих готовых редакций, их даты, снимки и исходные DOCX.
- **№2 и 5.** Проверка PR читает подтверждённый поток WSDL и применяет ожидающие данные к архивным ответам СФР, затем проверяет входящие документы, поля, воспроизводимость снимка, сайт, две проверки всех комплектов в WASM и Chromium. Pages при появлении нового текущего WSDL сохраняет обычный сбор. На одинаковых входах при фиксированном времени наблюдения локальные прогоны обеих ветвей дали идентичные указатель, каталог, индекс полей и данные сайта. Документация отличает ручную сетевую проверку WSDL от диагностики утреннего обновления и архивной проверки Pages.
- **№3 и 4.** Поиск WSDL обрабатывает каждый адрес отдельно и использует URL ресурса без фрагмента. Домашний сборщик проверяет ранее записанный манифест при отличающихся байтах. При восстановлении он выбирает самую раннюю имеющуюся подтверждённую квитанцию домашнего сборщика или SourceCraft. Если квитанций нет, используется время текущего валидного захвата. Исправный прежний манифест другого сборщика сохраняет своё содержимое.
- **№7 и 8.** При сравнении копий XSD имя входного файла исключается из ключа эквивалентности, остальные разрешённые пути и SHA-256 сохраняются. Каталог и импорт используют прежний ID при наличии эквивалентной одновременной публикации. Формула ID опубликованных редакций сохранена. Кодированный URI-путь сопоставляется с декодированным точным путём архива, в том числе при одинаковых basename в разных каталогах. В реестре WSDL сохраняется первоначальный URL, в ZIP используется декодированное имя.

## Проверки

До исправлений тесты воспроизвели изменение данных при отклонённой поставке, повторный отказ при старой `review`, ошибочное восстановление после прерывания очистки, остановку на некорректном порте, пропуск испорченного манифеста, неоднозначность после переименования XSD и при кодированном пробеле, лишний ID при добавлении раньше сортирующегося архива и отсутствие проверки потока в PR.

Выполнены две профильные команды в проектной Python 3.12.10, из корня репозитория.

```powershell
.venv/Scripts/python.exe -B -m unittest tests.test_fix22_update tests.test_update_catalog_lock tests.test_publication_build tests.test_journal tests.test_history_review_regressions -q
.venv/Scripts/python.exe -B -m unittest tests.test_fix22_sources tests.test_collector tests.test_wsdl_sources tests.test_schema_recovery tests.test_inbox_index tests.test_fix20_pipeline -q
```

Первая команда прошла 36 проверок, вторая — 69. Git не обнаружил ошибок пробелов в изменённых отслеживаемых файлах. Проверки использовали временные каталоги, локальные исходные байты и модель GitHub API. Общая сборка рабочего справочника и внешняя публикация в этот этап не входят.

## Дополнительные сценарии после ревью

- **№3.** До исправления считывание HTML со ссылкой `https://[not-an-ipv6]/` прерывало домашний захват до обращения к корректному WSDL на той же странице. Теперь разрешение каждой ссылки независимо. Проверка проходит через домашний сборщик и полный сбор с ZIP на вспомогательной странице.
- **№4.** Повтор локального `--capture-to` оставлял испорченный манифест на диске. Локальный и GitHub-режимы используют одни правила восстановления. Тест воспроизводит повреждение в локальном каталоге, проверяет восстановленный манифест, прежнюю квитанцию и следующий повтор.
- **№7.** Ручной импорт повторно выбирал XSD внутри ZIP после проверки входящих файлов. При появлении второй копии с более ранним именем он создавал новую редакцию. Теперь при выборе учитываются подтверждённые ID из каталога и прежний ID этой входящей поставки. Проверены одинаковые байты каталога после добавления копии, а также выбор прежнего ID, когда обе копии уже есть в истории.

```powershell
.venv/Scripts/python.exe -B -m unittest tests.test_fix22_sources -q
.venv/Scripts/python.exe -B -m unittest tests.test_collector tests.test_fix20_pipeline tests.test_source_collection_regressions tests.test_history_review_regressions tests.test_journal -q
```

Все три сценария воспроизведены до исправлений. После исправлений прошли 8 проверок первой команды и 53 проверки второй. `git diff --check` для затронутых исходников прошёл.
