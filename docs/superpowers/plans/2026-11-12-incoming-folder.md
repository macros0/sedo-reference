# Импорт спецификаций из GitHub

Пользователь предпочёл простой процесс: положить новые файлы в папку и push. Дополнительно попросил описать вклад через pull request в README.

Решение: incoming/prod и incoming/test, внутри можно создавать папки отдельных поставок. DOCX с номером сообщения в имени; ZIP рядом необязателен. Стандартные имена СФР и короткие 10110_v3.1.docx распознаются автоматически. Для нестандартных имён доступен необязательный metadata.json. XSD подбирается по корню/namespace; несколько разных подходящих схем требуют разных папок.

Обработка целого набора во временной копии; ошибка не меняет действующий справочник. state/inbox.json хранит обработанные хэши. Повторный запуск не создаёт редакций, добавленный позднее ZIP обрабатывается. Исторические редакции сохраняются при удалении исходников из incoming.

Проверка PR: read-only pull_request workflow, без секретов и публикации. После push/merge в main штатный Pages workflow импортирует набор, сохраняет проверенные state/data/site и публикует артефакт того же запуска. Подтверждением служит push или принятие PR. Права записи контролирует GitHub.

Проверки: метаданные оригинальных имён СФР, сухой запуск без изменения проекта, DOCX-only, поздняя XSD, повтор, плохой набор и неоднозначность. Прогнать проверки и реальный workflow без добавления фиктивных спецификаций в общую историю.

Локально проверено: 43 Python-теста, три Node-набора, verify.py, YAML и браузерная инструкция. Добавлены проверки отката при сбое второго файла, удаления уже обработанных исходников, повторной отправки существующего официального DOCX и изменения только метаданных. Независимое ревью нашло случай duplicate-only без созданного site во внешнем этапе; исправлен копированием уже проверенного результата предпросмотра, отдельная регрессия прошла.

README содержит стандартный путь участия через fork/PR, критерий подтверждения push/merge, примеры папок и необязательного metadata.json, сохранность истории, отчёты CI и необходимость git pull после служебного коммита импорта. Публичная страница «Добавить спецификацию» ведёт в папки; локальный загрузчик остаётся дополнительным вариантом.
