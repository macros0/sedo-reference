# Проверка XML и аудит таблиц спецификации

17 ноября 2026 года. Пункты 3, 11, 12 и 13 из [плана ревью](2026-11-17-review-current-tree.md).

| Пункт | Исправление и проверка |
| --- | --- |
| 3 | Скрипт из ZIP и браузер сначала проверяют исходное правило элемента. Если libxml2 отклонил эквивалентную запись логического значения, они проверяют тот же XML ещё раз. В дополнительных копиях схем только подтверждённый логический `fixed` заменён на `default`. Типы, `pattern`, строковые ограничения и выбор `xsi:type` сохраняются. Диагностики первичной проверки для противоположного логического значения или запрещённого `xsi:nil` сохраняют силу. Оригиналы в ZIP и рабочая входная схема содержат исходный `fixed`. Этот же механизм применяется к XML-примерам из DOCX. |
| 11 | Комплекты сохраняют признак полноты профилей именованных типов. При выборе `xsi:type` Python и WASM используют правила фактического типа для потомков. Отсутствие правил у конкретного типа снимает проверку, которая действовала для `anyType` его базы. Прежние манифесты читаются по прежней схеме. В тесте локальный `item` при выборе `Derived` допускает атрибут `true`, а глобальный `item` в `Base` отклоняет его из-за своего `fixed=false`. |
| 12 | Аудит модульного DOCX разрешает QName типа в области действия объявления из XSD-фрагмента. Для корня и вложенного элемента одинаковые локальные имена с разными известными URI дают замечания. Смена префикса при том же URI их не создаёт. Тест также охватывает отсутствующий префикс и прежнее сравнение текстовых строк таблиц. |
| 13 | Аудит отдельного тома учитывает известную примитивную базу и правила `whiteSpace` при сравнении `fixed` и `default`. Для `xs:boolean` совпадают `true/1` и `false/0`. Противоположные значения дают замечания к XSD-фрагменту и к строке свойств. У `xs:string` сохраняются значимые пробелы. |

## Результаты проверок

- До изменений тесты ZIP/Python и реального WASM отклонили допустимое значение `1` в продуктивном сообщении №701, редакция `bf8b73ced84609142e11520ec244a8e822c1071f61521ccbbd4bacd3a317be6a`. В Python также воспроизведён отказ для ` 1 `.
- После изменений обе реализации приняли `true`, `1`, ` 1 ` и пустой элемент. Для `false`, `0` и `yes` обе вернули ошибку на строке 2. Сквозной тест Python распаковал комплект, собранный из архивного оригинала этой редакции, и запустил его `validate.py`.
- Отдельный комплект проверяет `fixed="0"`, переносы строк вокруг значения, запрет `xsi:nil`, ограничивающий `pattern` именованного типа и строковый `fixed="true"`. WASM также проверяет сорок эквивалентных значений подряд и реальное нарушение после них.
- Отрицательная фаза для пунктов 11–13 дала три несовпадения в Python и одно в WASM. После исправлений все четыре сценария прошли. Совместный запуск пяти профильных модулей Python прошёл 99 тестов. Добавленный затем тест сочетаний ограничений также прошёл.
- Дополнительная регрессия с XSD-примером внутри `xs:appinfo` сначала помешала сборке из-за префикса из иллюстрации. После исключения аннотаций она прошла вместе с тестами №701 и ограничивающего шаблона.
- При первой полной пересборке данные `schema_review` совпали с исходной рабочей копией для всех 264 редакций. Список затронутых редакций аудита пуст. Браузерные проверки выполнены на реальном WASM, включая повторный запуск после изменения объединения диагностик.
- В первом прогоне Chromium на полной сборке семь сценариев прервались до нужного действия. Семь трасс Playwright содержат 14 отказов подключения к локальному HTTP-серверу (`net::ERR_CONNECTION_REFUSED` на `127.0.0.1:4173`). Среди запросов были HTML редакции и `review-journal.js`, а также скрипты загрузки валидатора. В Python 3.12 на этом компьютере очередь прослушивания тестового сервера равна 5. Для повторного прогона всех 48 неизменённых сценариев в той же сборке использована временная конфигурация сервера с очередью 128. Итог записывается в общий журнал приёмки.
