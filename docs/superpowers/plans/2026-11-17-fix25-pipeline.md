## Что изменено

| № | Реализация и проверяемое поведение |
|---|---|
| 1 | Общая `auto_update.validate_saved_history` защищает ID редакций, прежние события, источники событий и наблюдения. `update_catalog` вызывает её перед установкой как онлайн, так и офлайн. Удалить прежний `review` разрешается только при отсутствии готового дерева и наличии явного подтверждения `archived-reviews.json`; разрешено перенаправление его потомка на прежнюю готовую редакцию. Сохранение двух готовых редакций при неполной `history.json` проверено в обоих режимах, прежний каталог остаётся побайтно прежним. Существующие тесты первого импорта и архивирования `review` проходят. |
| 2 | Каталог сравнивает конкретное имя входного XSD без внешней папки, QName корня и digest относительных зависимостей. Переход `old/main.xsd` → `release/main.xsd` → `old/main.xsd` сохраняет ID; текущая редакция хранит настоящий путь и SHA текущего ZIP. Коллизии при изменении конкретного входного файла, корня или namespace остаются ошибками. |
| 3 | `document_metadata.document_history` распознаёт тройки заголовков Word; отдельное поле `document_history` содержит `{version,date,description}`. Таблицы соответствия XSD остаются в `version_tables`. История передаётся также в `document_sources` без дерева. `catalog._export` восстанавливает её по SHA из исходного DOCX, не меняя снимки. Для этой операции используется узкий `read_document_history`, читающий только `word/document.xml`; повторное построение привязок модулей исключено. Реальный test122/SHA `af85e31615ca…`: 49 строк от 2.1/02.12.2021 до 2.49/18.12.2025. Проверены архивные источники №317–319. Расширение `SOURCE_KEYS` и интерфейс выполнил основной агент. |
| 5 | `root_metadata` и `root_matches` задают общие правила каталога и inbox: отсутствие строки namespace разрешает любой URI подходящего корня, явно пустая строка требует схемы без namespace, явный URI требует совпадения. Второй полный кандидат с другим namespace вызывает отказ о неоднозначности. |
| 6 | История home перечисляется по отдельным подтверждённым `.observed-at` выбранного источника и валидным манифестам. Существующий ledger `manifests` принадлежит SourceCraft; home использует `sources.home`, поэтому переключение источника не подавляет работу. Проверены A→B→A с подтверждённым историческим DOCX, материализация промежуточной B и её события, повтор без изменений, переключение home→SourceCraft→home, а также явная причина недоступности при нехватке DOCX. |
| 7 | Производитель SourceCraft сохраняет первую дату отдельной квитанцией до установки указателя. Ремонт использует её либо ранее валидный манифест; для уже индексированного ID без надёжной даты он завершается явной ошибкой. Старый и чистый потребители восстановленной ленты видят прежнюю дату; импортёр сохраняет собственную уже подтверждённую квитанцию. `load_library` распознаёт также подтверждённый `index.json` локального производителя. |
| 8–10 | Вспомогательные страницы обходятся с сохранением query и контекста редиректа; прежняя нормализация официальных alias и повторных `/` сохранена. Относительные ссылки учитывают HTML `base` относительно окончательного URL. Пустая подпись дубликата заполняется содержательной до разбора версии/даты; байты загружаются один раз. Разрешения хоста и контура продолжают проверяться. |
| 11 | CLI `sync.py` использует общую `catalog_locks`: вложенный `data/nested-state` разделяет блокировку проекта и отказывает до записи, автономная директория продолжает работать. |
| 12 | Проверка WSDL нормализует пути согласованно, отдельно разрешая собственный query сервиса. Завершающий `/` сохраняет границу разрешённого каталога: `/nested/Service/?wsdl` принимает собственный `?xsd=1` и `schemas/a.xsd`, но отклоняет соседний `/nested/other/a.xsd` и другой хост. |

Новые правила снимка активируются в формате 6. Явное воспроизведение форматов 1–5 сохраняет прежние правила, включая подписи, `base`, query и отсутствие нового поля истории. Тесты проверяют побайтное повторное воспроизведение моделей форматов 5 и 6. Основному агенту передано добавить 6 в перечень точной проверки `verify.py`.

При проверке сохранности допускается только добавление ранее отсутствовавшего `document_history` в источники; остальные прежние значения и события должны совпадать.
