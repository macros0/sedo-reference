# Ручная загрузка спецификаций

Цель: владелец загружает полученные отдельно DOCX и необязательный ZIP с XSD, проверяет редакцию и сохраняет её в общей истории. Экран работает локально в браузере; публикация — отдельное действие пользователя через существующий GitHub-репозиторий.

Принятый рабочий вариант: поддержать оба вида поставки и два действия после предпросмотра — сохранение локально и сохранение с публикацией. Нового сервиса хостинга и секретов в публичном сайте не требуется. Текст документов не редактируется.

Хранение: отдельные снимки source_type=manual в общей истории, с оригинальными байтами в state/objects. Официальный current.json и время проверки СФР не меняются. DOCX без XSD получает статус document_only; архив и запись журнала доступны, дерево и числовое сравнение отсутствуют. Автообновление сохраняет такие редакции. Повторный импорт не создаёт дубликат; последующее появление той же редакции на СФР сохраняет первую дату обнаружения.

План:
- Проверки: предпросмотр не меняет проект, DOCX без XSD, сопоставление XSD, дубликаты, невалидный файл, сохранение после автообновления.
- Импорт в изолированной временной папке, проверка старой истории и сохранение после подтверждения.
- Локальная форма с метаданными и предпросмотром; сервер слушает только 127.0.0.1, изменения требуют токен с локальной страницы.
- Отметки ручного источника и отсутствующей схемы в каталоге/журнале; архив DOCX сохраняется.
- Явная публикация проверенного результата через Git, проверки и документация запуска.

Публиковать загруженные владельцем файлы автоматически при выборе не требуется: сначала предпросмотр, затем кнопка подтверждения. Неоднозначная или неподдерживаемая XSD останавливает импорт с объяснением.

Пользователь подтвердил: общий публичный справочник после предпросмотра/подтверждения; бывают поставки DOCX и DOCX+XSD. Дополнительно потребовал доступ только для себя. Реализованы локальный bind, токен/Host/Origin, проверка аккаунта macros0 и фиксированного репозитория перед Git push. Публичный сайт содержит только инструкцию входа владельца.

Результаты проверки: полная Python-проверка 33 теста прошла; затем отдельно проверены добавленные ограничения сохранения/путей и реальный браузерный сценарий. Все три Node-набора прошли. Браузер загрузил DOCX через multipart, сформировал предпросмотр без изменения проекта, сохранил после подтверждения, распознал повтор и восстановил публикацию после перезапуска. Git-публикация и повтор после сбоя проверены на временном локальном bare-репозитории; тестовые данные в рабочий справочник не добавлялись.

Независимое ревью выявило и помогло закрыть два случая: теперь fingerprint покрывает все продвигаемые файлы, а публикация хранит служебную квитанцию в Git с восстановлением после закрытия загрузчика. Подтверждённое сохранение допускается только из чистого main либо неизменённого состояния предыдущего подтверждённого импорта; чужие правки не включаются в публикацию.
