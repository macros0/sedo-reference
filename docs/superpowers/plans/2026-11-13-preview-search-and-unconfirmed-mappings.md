# Preview Search and Unconfirmed Mappings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans.

**Goal:** Поиск по тегам/описаниям и фильтр «Только предложенные» в предпросмотре; явное подтверждение заполненных Excel-пар, ранее пропущенных из-за статуса.

**Architecture:** parseWorkbook сохраняет отдельные кандидаты без изменения confirmed-only pairs. preparePreview объединяет их с относительными предложениями, отдавая ручным строкам приоритет. Таблица фильтруется и пагинируется без изменения выбора или набора применения.

**Tech Stack:** существующие Vanilla JavaScript/ExcelJS/Node tests.

## Root cause
Пользовательский XLSX 105/10510: заполнены все 16 путей, но 8 строк имеют «Подтверждено», 7 — «Не проверено», одна — «Переработано». Старый импорт читает только 8 подтверждённых и точно воспроизводит 8 удалений/11 добавлений. Относительные предложения покрывают 7 из пропущенных; socialAssistNum→processNum имеет разный относительный путь и требует подтверждения заполненной Excel-пары. Исходный пользовательский файл не редактируется и не коммитится.

## Decisions
- Заполненные пары «Не проверено»/«Переработано» предлагаются в предпросмотре; «Требует уточнения» предлагается без выбора по умолчанию. Статус «Удалено» не становится предложением Excel.
- Подтверждённые пары применяются как прежде. Неподтверждённые пары не меняют сравнение до явной кнопки применения. Ошибочные неподтверждённые пути видны как предупреждения, а не молча теряются.
- Заполненные неподтверждённые ветви имеют приоритет над автоматическими относительными предположениями, но их потомки до подтверждения не угадываются.
- Поиск: обе стороны, имя/полный/относительный путь, описание и комментарий. Несколько слов, регистр/ё не мешают.
- Фильтры сбрасывают номер страницы, сохраняют выбор и не ограничивают применение. Количество видимых и отмеченных пар показано отдельно; весь отфильтрованный список доступен по страницам.

- RED воспроизведён для отсутствующих preparePreview/candidates; GREEN после реализации.
- Синтетический публичный fixture 105/10510 подтверждает 8 fixed + 8 pending → 16 принятых → 0 удалённых, только 3 новых атрибута.
- На предоставленном XLSX браузерный цикл HTTP (широкое/узкое окно) и file:/// проверил поиск по обеим сторонам/описаниям, фильтр, сохранение выбора, 16 применённых пар, выгрузку и reload. Исходный файл не изменён (SHA до/после совпадает).
