# Код-ревью Справочника СЭДО и план исправлений

15 ноября 2026 года. Основная версия для исправлений — [GitHub main, `7e88804`](https://github.com/macros0/sedo-reference/commit/7e888049c564c5bfcc048c366eafaf07ba5e8577). Локальная ветка `main` на `8509bb6` отстаёт на 101 коммит и содержит собственные изменения. Ссылки ниже закреплены за проверенным коммитом.

Проверены сбор и импорт источников, хранение снимков, построение каталога и деревьев, аудит DOCX, журнал и статус, браузерное сравнение и Excel, проверка XML, генерация сайта и workflows публикации. Для основного прогона использовалась отдельная копия точного коммита. Внешние сервисы СФР, конфигурация сервера SourceCraft и права GitHub Environment в проверку не входили. Минифицированные зависимости проверялись через поведение приложения.

## Замечания

| № | Приоритет | Дефект, условие и наблюдаемый результат |
|---|---|---|
| 1 | P1 | **В Windows готовый XML-валидатор не открывается при `core.autocrlf=true`.** Git преобразует шесть JS-модулей в CRLF, а встроенный манифест сохраняет хеши LF. В Chromium 6 из 16 штатных сценариев остановились с ошибкой контрольной суммы. Та же настройка меняет байты 43 из 151 скачиваемой исходной XSD: файл отличается от SHA-256 в его имени. Для всех этих файлов исходные Git-блобы совпадают с соответствующими SHA-256. [Атрибуты Git](https://github.com/macros0/sedo-reference/blob/7e888049c564c5bfcc048c366eafaf07ba5e8577/.gitattributes#L9), [манифест сборки](https://github.com/macros0/sedo-reference/blob/7e888049c564c5bfcc048c366eafaf07ba5e8577/build_site.py#L106), [проверка перед открытием](https://github.com/macros0/sedo-reference/blob/7e888049c564c5bfcc048c366eafaf07ba5e8577/web/validation.js#L28), [выдача исходной XSD](https://github.com/macros0/sedo-reference/blob/7e888049c564c5bfcc048c366eafaf07ba5e8577/source_provenance.py#L50). |
| 2 | P1 | **Теряется `fixed` у ссылки на атрибут.** При раскрытии `ref` построитель поля берёт ограничения из глобального объявления. В продуктивном сообщении 100 v2.28 у `confirmationRequest/benefit1Approve/elnInfo/code/@editable` в XSD стоит `fixed="false"`, в дереве — пустой `flags`. Карточка и сравнение пропускают существенное ограничение. Такая конструкция есть и в сообщении 101. [Разрешение ссылки](https://github.com/macros0/sedo-reference/blob/7e888049c564c5bfcc048c366eafaf07ba5e8577/schema.py#L162), [заполнение flags](https://github.com/macros0/sedo-reference/blob/7e888049c564c5bfcc048c366eafaf07ba5e8577/schema.py#L170). |
| 3 | P1 | **Оба валидатора принимают недопустимое значение этой конструкции.** На минимальной схеме с глобальным булевым атрибутом и `fixed="false"` на его локальном использовании браузерный WASM и проектный lxml 6.1.3 / libxml2 2.11.9 приняли `true`. Независимый .NET-валидатор отклонил `true` и принял `false`. В контролях с ограничением непосредственно на объявлении lxml отклонил `true`. Проверена конструкция из реальных схем, целое сообщение страхователя для опыта не использовалось. Исправление только карточки оставит ложный успешный результат проверки XML. [Браузерная проверка](https://github.com/macros0/sedo-reference/blob/7e888049c564c5bfcc048c366eafaf07ba5e8577/web/validation-worker.js#L23), [проверка из скачанного ZIP](https://github.com/macros0/sedo-reference/blob/7e888049c564c5bfcc048c366eafaf07ba5e8577/xsd_validate.py#L79). |
| 4 | P1 | **Тест публикации ломается при следующей продуктивной редакции 10110.** Он выбирает первую известную редакцию A в истории. Когда в каталоге уже есть A и B, тест добавляет C и требует, чтобы предшественником была A. На последовательности A → B → C экспорт вернул B. Пока в проверенном каталоге одна продуктивная редакция 10110, тест проходит. С новой редакцией следующая проверка Pages может остановить выпуск уже собранного каталога. [Выбор предыдущей редакции](https://github.com/macros0/sedo-reference/blob/7e888049c564c5bfcc048c366eafaf07ba5e8577/tests/test_auto_update.py#L136), [проверка журнала](https://github.com/macros0/sedo-reference/blob/7e888049c564c5bfcc048c366eafaf07ba5e8577/tests/test_auto_update.py#L144). |
| 5 | P2 | **Аудит DOCX перестал охватывать часть таблиц именованных типов.** Для сопоставления берётся пространство имён XML-поля. Локальный элемент может быть без пространства имён, а его тип объявлен в пространстве имён XSD. На тех же редакциях число проверок сократилось с 21 508 до 21 268 в десяти номерах сообщений. Воспроизведено для карточки `NoticeSendType` в продуктивном 110 v2.28. Ранее выданные замечания в сравниваемых данных сохранились. [Фильтр карточек типа](https://github.com/macros0/sedo-reference/blob/7e888049c564c5bfcc048c366eafaf07ba5e8577/audit_module_tables.py#L124). |
| 6 | P2 | **Необязательный блок показан как выбор одного варианта.** В тестовом 10010 v3.0.4 поля `parentProcessNum`, `subProcessReasonCode` и `subProcessReasonDetails` входят в одну `sequence [0..1]`. При наличии блока обязательны все три. Карточка каждого поля говорит «Вариант выбора». Путь вставки текста также заменяет объявление до разбора. [Определение кодировки](https://github.com/macros0/sedo-reference/blob/7e888049c564c5bfcc048c366eafaf07ba5e8577/web/validation-core.js#L10), [обработка файла](https://github.com/macros0/sedo-reference/blob/7e888049c564c5bfcc048c366eafaf07ba5e8577/web/validation-worker.js#L16), [вставка текста](https://github.com/macros0/sedo-reference/blob/7e888049c564c5bfcc048c366eafaf07ba5e8577/web/validation-frame.js#L63). Воспроизведено на штатном редакторе с общим хранилищем. Обработчик записывает весь набор из снимка при открытии. [Создание черновика и применение](https://github.com/macros0/sedo-reference/blob/7e888049c564c5bfcc048c366eafaf07ba5e8577/web/comparison-mapping.js#L204). |
| 9 | P2 | **Прерванная запись делает повторный импорт SourceCraft невозможным.** Объект сразу пишется под окончательным именем SHA-256. В изолированном импорте двух реальных манифестов запись была прервана после 12 байт. Указатель не продвинулся, но повторная попытка прочитала обрывок как существующий объект и завершилась `Feed object SHA-256 mismatch`. Для восстановления потребуется вмешательство. ## План исправления

- [ ] **1. Обеспечить идентичность публикуемых файлов на Windows и Linux** (№ 1). Для хешируемых JS-модулей в `web/` и `site/` закрепить LF через `.gitattributes`, для байтовых оригиналов в `site/sources/*.xsd` отключить текстовое преобразование. В чистом checkout с `core.autocrlf=true` сверить SHA-256 всех восьми ресурсов валидатора и всех XSD с именами файлов. Прогнать браузерные сценарии до локальной пересборки, затем повторить после неё. Проверка SHA-256 в приложении должна сохраняться.
- [ ] **2. Сделать тест выпуска независимым от состава текущего каталога** (№ 4). В `tests/test_auto_update.py` поместить сценарий смены версии на фиксированный снимок с A и B. При добавлении C ожидать B, проверить сохранность обоих прежних документов и деревьев. Отдельно прогнать тест при отсутствии 10110 в актуальном перечне. Это снимает риск блокировки следующих исправлений при выпуске.
- [ ] **3. Восстановить правила XSD в данных и в проверке XML** (№ 2, 3). В `schema.py` сохранять эффективные `fixed/default` конкретного использования атрибута с учётом глобального объявления. Проверить дерево, карточку и сравнение при смене ограничения. Независимо проверить обработку этого правила в WASM и Python: поменять версию движка, если она проходит контрольный набор, либо добавить ограниченную дополнительную проверку. Закрепить отдельными проверками `false`, `true`, `0` и `1` с учётом применяемой версии XSD. Приёмка — одинаковый вердикт обоих валидаторов и контрольного .NET, разрешение отсутствующего необязательного атрибута и корректное отображение в сообщениях 100/101. [W3C, правило проверки использования атрибута](https://www.w3.org/TR/xmlschema-1/#cvc-au).
- [ ] **4. Вернуть охват аудита и исправить подписи блоков** (№ 5, 6). Экспортировать пространство имён объявления именованного типа и использовать его при сопоставлении таблиц. На карточке `NoticeSendType` проверить как успешное соответствие, так и появление замечания при намеренно изменённом описании в тестовой копии DOCX. Для групп различать `choice` и `sequence`, сохраняя признаки вложенного выбора. Проверить карточки трёх полей 10010 и поле настоящего `choice`. Пересобрать производные деревья исторических редакций, сохранив архивные оригиналы, идентификаторы и ссылки.
- [ ] **5. Устранить ложный успех для объявления XML** (№ 7). До перекодирования проверять синтаксис объявления на путях файла и вставки. Пустая кодировка должна завершаться ошибкой. Прогнать допустимые UTF-8, UTF-16 и Windows-1251, проверить сохранение координат подсветки в исходном тексте.
- [ ] **6. Сделать хранение снимков восстанавливаемым** (№ 9, 10, 18). Объекты и манифесты писать через временный файл в том же каталоге с заменой после полной записи и проверки. Для уже существующего неполного объекта разрешить восстановление из проверенного источника по ожидаемому хешу. Указатель продвигать последним. В `verify.py` завершаться с диагностикой отсутствующего обязательного объекта. В генерации вложенных ZIP зафиксировать платформенные поля заголовка, включая `create_system`, и разбирать суффиксы URL через `PurePosixPath`.
