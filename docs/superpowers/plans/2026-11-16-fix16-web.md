## Изменения и подтверждение регрессий

| № | Воспроизведение до исправления | Исправление и проверка |
|---|---|---|
| 11 | Две XSD с одним официальным URL и путем, но разными SHA, давали один вариант фильтра. | SHA входит в ключ и подпись XSD. Сохраняется чтение старых закладок, выбирающих все версии по прежнему адресу. `finding.xsd_source` имеет приоритет над разбором `xlocation`; архивный файл `sources/<sha>.xsd` отделен от официальной публикации. В Excel колонка M ведет на архивные байты, отдельная добавленная колонка — на официальный XSD. Node проверяет два разных SHA, отдельную выборку и XLSX-ссылки; добавлен Chromium-сценарий. |
| 12 | Корректная XSD с двумя последовательными `item` получала `ready`, хотя пути повторялись. | После существующего допустимого объединения альтернатив проверяется уникальность XML-путей в `fields.build`. Неоднозначный отдельный том получает `review` с `r/item`, JSON дерева не записывается. Регрессия предварительно подтверждает XML через lxml и проверяет статус через реальный export entrypoint. |
| 13 | Сравнение `(a,b)? (c,d)?` и `(a)? (b,c)? (d)?` не показывало изменения. | Сохраняется прежний массив `contentModel`; добавлено дерево `contentModelBounds` с `kind/min/max/children`, включая границы использования именованной группы. Новый движок использует границы, когда они есть с обеих сторон, и читает прежние деревья прежним способом. Выравниваются только обязательные `sequence[1..1]`, границы необязательных и повторяемых групп сохраняются. Проверены исходные XSD/lxml → Python-дерево → JS comparison, счетчик журнала и XLSX roundtrip. Обязательная вложенность и эквивалентная именованная группа не дают ложной разницы. |
| 14 | На 100 000 дочерних элементах WASM возвращал runtime, поскольку дополнительная проверка атрибутов зависела от ограниченного индекса навигации. | XML-сканер выделен в потоковый генератор `scan`. Навигация сохраняет прежние пределы и может потерять подсветку. Атрибутная проверка обходит весь документ, хранит только активных предков, профили типов и ограниченный бюджетом набор фактических проб. Диагностические записи не удерживают дерево предков. Настоящий WASM принимает большой допустимый XML и отвергает неправильный `fixed` после 100 000 элементов, сохраняя строку ошибки. Остались проверки `xsi:type`, QName, пространств имен, повторов и эквивалентных boolean. |
| 15 | В обоих workflow после сборки отсутствовал запуск профильного теста дополнительных XSD с `--all-editions`. | В `pages.yml` и `check-sfr.yml` добавлен этот запуск после построения кандидата и до Git push. Тест порядка команд сначала падал на обоих workflow, затем прошел. WASM дополнительно получает поврежденную вспомогательную XSD с `MissingProbeType` и подтверждает отказ компиляции; тот же helper компилирует готовые кандидаты. |
| 16 | Карточка 600 в prod содержала также модуль тестового контура. | Модули вычисляются из строк выбранного контура и выводятся без повторов. Режим всех контуров показывает объединение. Node-регрессия на настоящем 600 прошла красную и зеленую фазы; добавлен Chromium-сценарий для prod/test/all. |
