# Независимая проверка исправлений конвейера

Проверены пункты 1, 7, 10, 12, 16, 19 плана `2026-11-17-review-production-data-and-import.md`: актуальные `build_site.py`, `verify.py`, `auto_update.py`, `manual_import.py`, `import_inbox.py`, `update_catalog.py`, `sync.py`, `automation_status.py` и связанные регрессионные тесты. Проверка статическая, с воспроизведением восстановления на временных каталогах; внешние сервисы и публикация не запускались.

## Вывод

Найденный при независимой проверке остаточный дефект пункта 12 исправлен по согласованию с основным исполнителем. Других подтверждённых замечаний в перечисленных исправлениях не найдено.

- **1. Идентичность полей.** Загрузчик сайта проверяет внутренний `revision_id` до чтения дерева из JSON; индекс ранее проверяется на точный набор уникальных редакций и готовые статусы. `verify.py` дополнительно сопоставляет внутренний ID каталогу. Рабочая публикация через CLI строится во временном каталоге до установки. Новая регрессия подменяет только внутренний ID.
- **7. База текущего генератора.** `build_history_baseline` строит `previous-fields` из прежнего каталога и сохранённых объектов текущим генератором. Вызов стоит до обработки новых входов во всех трёх путях: `_run` (включая историю коллектора), `_prepare_import` и `_process_inbox` (включая `--check`). Прежний каталог не заменяется пересчитанным; `validate_history` продолжает сравнивать прежние события, источники наблюдений, ID и пересчитанные старые деревья. `fields.build` проверяет хеш архива, поэтому пересчёт не отменяет контроль сохранённых байтов. Проверена новая регрессия совместного изменения генератора и pending incoming, а также существующие проверки PR/Pages.
- **10. Query IRI.** `request_query` кодирует не-ASCII, сохраняет существующие `%HH`, плюс, повторы и разделители; `_get` применяет его только к HTTP target. Исходный URL остаётся в инвентаре. `download_key` использует ту же нормализацию для объединения загрузок. Интеграция действует для WSDL-зависимостей, вызывающих обычный транспорт.
- **12. Владение восстановлением.** Первоначальная проверка только допустимых имён каталогов всё ещё удаляла `candidate/data/operator-notes.txt` и `data/fields/operator-notes.txt` без признака транзакции. Это воспроизведено на временных каталогах (оба файла исчезали). Основной исполнитель добавил `preparing`, создаваемый до копирования, и отказ для непустого каталога без признаков транзакции. Дополнительно устранена потеря признака при прерванной очистке: оба recovery-пути теперь используют существующий `cleanup_site_recovery`, который атомарно записывает `cleanup.json` с путями и хешами перед первым удалением, проверяет оставшиеся файлы и возобновляет очистку без повторного отката. Допустим `cleanup.partial` после прерванной записи маркера. Регрессии проверяют посторонний вложенный файл без признака транзакции, файл рядом с настоящим журналом, очистку после удаления `preparing` и `committed`, несколько вариантов оставшихся резервных каталогов и повторный recovery.
- **16. Старый формат публикации.** Вместо первых трёх SHA проверяются все подходящие по времени запуски в том порядке, в котором `build_status` выбирает результат; одинаковые SHA используют общий результат чтения `checked_at`. Ограничение в три запроса снято. Современный путь с `publication-target.json` остаётся отдельным и не использует этот поиск.
- **19. Свидетельство deploy.** Для завершённой неуспешной/отменённой попытки читаются задания конкретной попытки с пагинацией. Успешный `deploy` даёт состояние success и фактическое время завершения deploy независимо от более позднего refresh-status. Нормализация применяется как к текущим, так и к историческим/предыдущим попыткам. Отмена до deploy остаётся cancelled. Проверены новые регрессии прямого evidence и `collect_status`.

## Верификация доработки восстановления

Усиленные старые регрессии сначала подтвердили проблему прерванной очистки: два теста дали пять ошибок после удаления `preparing` и `committed`. После доработки четыре целевых теста завершились **OK**. Обработчики прерывания в `test_review_regressions.py` и `test_fix22_update.py` перенесены с прежнего `shutil.rmtree` на фактический API `Path.unlink` внутри очистки; смысл проверок сохранён, удаление обоих маркеров добавлено явно.

Расширенный прогон `.venv/Scripts/python.exe -m unittest tests.test_review_regressions tests.test_fix22_update tests.test_fix19_pipeline tests.test_update_catalog_lock` — **33 теста, OK** (30,817 с).
