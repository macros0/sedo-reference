Абсолютный XPath ошибки разрешается относительно документа SOAP. [Извлечение данных](../../../audit_xml_examples.py#L278) · [Разрешение XPath](../../../audit_xml_examples.py#L312)

### P2 — деревья, сравнение и валидация

12. **Отдельный том получает статус готового дерева с неоднозначными путями.** Для валидной последовательности двух одноимённых `item` построено `[r, r/item, r/item]`. lxml принимает XML с обоими элементами. Сравнение дерева с самим собой падает, а прямая ссылка выбирает первый `item`. В 264 текущих деревьях повторов пути нет. Для модульных томов уже есть проверка такого случая. [Статус дерева](../../../fields.py#L25) · [Проверка модульных томов](../../../module_xsd.py#L251) · [Индекс сравнения](../../../web/compare-core.js#L53)

(d)?` результат сравнения пуст. lxml принял `<r><a/><b/></r>` только по первой схеме и `<r><a/></r>` только по второй. Журнал и Excel используют тот же движок. В текущих деревьях встречаются необязательные вложенные последовательности, пример смены контракта воспроизведён на двух контрольных редакциях. В этом случае лимиты ввода в 10 МиБ и времени в 30 секунд не достигнуты. [Лимит навигации](../../../web/validation-paths.js#L31) · [Проверка ограничений](../../../web/validation-worker.js#L66)
