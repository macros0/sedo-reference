# Журнал появления редакций

Запрос: видеть, когда и какие редакции появились в справочнике, сравнивать их и скачивать оригиналы.

Решение: сохранять время первого успешного получения каждого снимка в state/observations.json, восстанавливать события из неизменяемой истории снимков при catalog.export. Одна редакция — одно событие. Дата документа СФР отображается отдельно от обнаружения. Неизвестное время не выдумывается. Исходные даты первых двух снимков восстанавливаются из сохранённых отчётов сборщика.

Предыдущая редакция берётся из ранее обнаруженных редакций того же номера и контура. Новинки одного снимка не считаются предшественниками друг друга. Первое наполнение помечается отдельно. Если предыдущей редакции нет, предлагается сравнение с доступным другим контуром. Удаление или возврат ссылки СФР не создаёт повторных событий появления.

- [x] Проверки дат, идемпотентности, замены DOCX/схемы, разделения контуров, удаления и возврата редакции, неуспешного обновления.
- [x] Сохранение дат в sync, событий в catalog и проверка их сохранности перед публикацией.
- [x] Журнал с поиском и фильтром контура, ссылками на дерево, DOCX и сравнение; общий вход и вход для сообщения.
- [x] Восстановление дат, сборка, Python/Node-проверки и просмотр в Edge.

Проверено: 17 Python-тестов, Node-проверки сравнения, verify.py, статическая сборка. Edge: общий журнал, фильтры сообщения и контура, пустой результат, ввод в поля, сохранение адреса, переходы и направление сравнения на примере добавленной редакции в тестовом наборе; проверен внешний вид. При проверке исправлен точный поиск номера: сообщение 12410 упоминает 10110 в названии, но не должно попадать в журнал сообщения 10110.

Публикация: push в main запускает штатный Publish reference; после развёртывания проверить публичный каталог и ссылки журнала.

Стек остаётся прежним: Python standard library и статические HTML/CSS/JS, включая локальный просмотр без сервера.
