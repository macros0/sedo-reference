# Сопоставление схем и проверка таблиц DOCX

Исправления №6, 9, 10, 12–15 из [плана ревью](2026-11-17-full-review-and-fixes.md) проверялись на архивных спецификациях и небольших примерах, в которых можно независимо проверить результат.

## Изменения

| № | Поведение и проверка |
| --- | --- |
| 6 | Полный XML-пример `<result/>` и встроенная XSD без `targetNamespace` подтверждают пустое пространство имён. Оно участвует в сопоставлении даже при наличии таблицы `DocumentType` с тем же именем корня. Таблица без сведений о namespace по-прежнему допускает выбор по имени. У тестовой пары схем выбирается именно схема без пространства имён. |
| 9 | Вспомогательная схема для проверки `fixed` импортирует файл со схемой-владельцем. Включённый в неё файл без `targetNamespace` получает пространство имён владельца. Для атрибута с именованным типом сохраняется эффективное пространство имён ссылки, для вложенного типа сохраняются области действия XML-префиксов. В тесте разрешённый `OK` проходит проверку Python и WASM, значение, противоречащее `fixed`, отклоняется. Отдельная проверка вложенного типа использует префикс, заданный только на корне включённого файла. |
| 10 | При сравнении модульных XSD имена типов и значения типа `xs:QName` сравниваются с учётом URI. Идентичность проверяется и для именованного ограничения из импортированного файла. Значения `xs:string` сохраняют буквальное написание. В XPath селектора и поля учитывается namespace фактически использованного префикса. При неизвестном типе сравнение сохраняет лексическую форму и привязки префиксов. |
| 12 | Текст встроенной XSD и значения фасеток извлекаются из Word с исходными внутренними пробелами. Исправления значений `fixed` и `default` в таблицах свойств и атрибутов проверяются также в [журнале конвейера](2026-11-17-fix22-pipeline.md). |
| 13 | Одинаковые эффективные границы `minLength` и `maxLength` дают точную длину. Различающиеся границы сохраняют диапазон. Тесты сравнивают документ с двумя типами, имеющими границы [5, 5] и [4, 5]. |
| 14 | Проверка отрицательного значения учитывает `fixed`, перечисление и шаблон. При дополнительных ограничениях для утверждения о принятии нужен отрицательный пример, который проходит проверку поля. Остаточная неопределённость отражается в покрытии. Проверки предельных значений `float` и `double` описаны также в журнале конвейера. |
| 15 | В замечаниях о кратности и использовании ссылка ведёт к месту объявления `minOccurs`, `maxOccurs` или `use`. Когда локальная ссылка и глобальная декларация находятся в разных XSD, проверка указывает конкретный файл, где задано проверяемое ограничение. |

## Исторические снимки

Снимки форматов 1–3 при воспроизведении используют прежние правила для пространства имён корня, сравнения модульных XSD и разрешения URI зависимости. Исправленные правила применяются при новом наблюдении. Снимок получает формат 4, когда результат может зависеть от этих правил.

В архивных документах нашлись пять привязок с доказанным пустым namespace. У документов №115 обе схемы уже были без пространства имён. Три привязки относятся к №317, где пример явно содержит `xsi:noNamespaceSchemaLocation="Application.xsd"`. При повторном сопоставлении двух прежних привязок старый сборщик выбирал XSD с квалифицированным корнем. Исходные снимки и их прежние решения сохраняются.

Сквозной тест использует один DOCX с квалифицированным корнем и два ZIP, в которых схема отличается только префиксом `xs` или `xsd`. В форматах 2 и 3 остаётся историческое замечание о неоднозначности. При новом сборе выбирается одна XSD и сохраняется формат 4. В каждом из трёх случаев повторный сбор с указанным форматом дал тот же SHA-256. Независимая проверка сравнила результат для формата 2 непосредственно с версией сборщика до исправлений.

## Проверки

- Первичные профильные регрессии дали шесть несовпадений и одну ошибку компиляции схемы. После основных исправлений прошли 73 теста из `test_embedded_xsd`, `test_audit_module_tables`, `test_audit_individual_tables`, `test_field_review_sources` и `test_attribute_ref_constraints`. Проверка комплекта в WASM прошла также через `tests/test_attribute_ref_constraints.cjs`.
- Три дополнительных примера из независимого ревью до последних правок дали два несовпадения и одну ошибку компиляции XSD. После исправления прошли все три и сквозная проверка форматов. Четыре теста заняли 0,451 с. Префиксы SHA-256 сквозного примера составили `7bd50b6a` для формата 2, `7dc0b369` для формата 3 и `9dc6a799` для формата 4.
- Результаты общей офлайн-сборки, сравнения каталога и браузерных проверок ведутся в [основном журнале](2026-11-17-fix22-progress.md).
