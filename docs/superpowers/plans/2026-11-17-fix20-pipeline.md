# Исправления сбора и архивного повтора

17 ноября 2026 года. Замечания №6–9 и №16 из [плана ревью](2026-11-16-review-replay-and-publication.md).

| № | Изменение | Проверка |
|---|---|---|
| 6 | Исторический повтор учитывает каждый объявленный корень модульного DOCX. При полной потере схем журнал записывает `unavailable`, при частичном результате сохраняет найденные редакции и причины для пропущенных сообщений. Прежние записи `replayed` проверяются по архивным входам. | В истории A → B → A у B исчез корень сообщения 999. В одном тесте восстанавливать нечего, во втором восстановлено сообщение 998 и указана причина для 999. Следующий запуск не требует повтора. |
| 7 | Сборщик разрешает относительные ссылки от конечного адреса HTML. При редиректе снимок сохраняет исходный и конечный адреса, а офлайн-проверка восстанавливает их при чтении сохранённых байтов. | Перенесены основная и дополнительная страницы. Найдены относительный DOCX и ZIP. Повтор сохранил SHA снимка. |
| 8 | Для ZIP дополнительных страниц используется список разрешённых хостов соответствующего контура. Снимок фиксирует формат 3 при любом изменении выбора URL по сравнению со старыми правилами, включая отклонённые ссылки. Алиасы остаются в перечне ссылок и используют одни скачанные байты. | Проверены продуктивный алиас с фрагментом, основной адрес и ссылка в тестовый контур. Получен один ZIP с двумя ссылками. Старый снимок формата 2 воспроизведён по исходным правилам. Для страниц со ссылками по HTTP, с портом 8443 и нечисловым портом проверены сбор исправного основного ZIP и точный офлайн-повтор. |
| 9 | Для непрозрачных идентификаторов XSD в query генерируется стабильное имя файла. Распаковка и разрешение импортов используют тот же идентификатор. Оригинальные WSDL и XSD сохраняются побайтово. | Схема по `?xsd=1` импортирует `?xsd=2` того же endpoint. Проверены ограничение из второй схемы, исходные байты обеих XSD, компиляция скачиваемого комплекта и повтор манифеста. |
| 16 | Перед публикацией домашний сборщик сравнивает Git blob SHA каждого полученного объекта с Git-деревом. Проверенными байтами восстанавливается повреждённый объект. Зафиксированные даты первого получения сохраняются. | Тест с локальной моделью Git API восстановил прежнее дерево после подмены одного объекта. Повтор завершился без изменений. |

Шесть исходных регрессий воспроизвели дефекты до исправлений. После изменений прошли 115 профильных Python-тестов. По итогам повторного ревью добавлен седьмой тест на отклонённые ссылки. До корректировки все три варианта завершились ошибкой, после неё каждый снимок воспроизвёл свой SHA. Изолированные установки домашнего сборщика и SourceCraft воспроизвели сохранённые манифесты обоих контуров с наборами файлов из инструкций.

`python verify.py` дважды воспроизвёл SHA `6581db63a1768b984f134e7b4cdae74f1a320df056ecd0aa6aa6a6a22a9839b7` для 145 ссылок и 110 скачиваемых файлов. Проверка использовала локальные архивы. Регрессии находятся в [test_fix20_pipeline.py](../../../tests/test_fix20_pipeline.py).
