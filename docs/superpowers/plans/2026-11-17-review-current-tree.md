### 3. P1. Валидатор сообщения №701 отклоняет допустимый XML

`web/validation-worker.js:105–109`, `xsd_validate.py:42–49,173`. В продуктивной редакции `bf8b73ce…` элемент `restrictionResponse/notIdentified` объявлен как `xsd:boolean fixed="true"`. Независимый System.Xml принимает `true` и `1` и отвергает `false`. В текущих деревьях найдено 74 вхождения элементов с фиксированным логическим значением. Правила типа определяют четыре допустимые записи для двух логических значений. [W3C, boolean](https://www.w3.org/TR/xmlschema-2/#boolean) · [W3C, проверка фиксированного значения элемента](https://www.w3.org/TR/xmlschema-1/#cvc-elt)

- [x] Добавить сквозные тесты на настоящем комплекте №701 в `tests/test_browser_validation.cjs` и `tests/test_xsd_bundle.py`. Проверить `true/1`, `false/0`, пустой элемент и неверное лексическое значение.
- [x] Исправить проверку фиксированного значения элемента в обоих валидаторах. Если для этого потребуется адаптация схемы, делать её в производной схеме валидатора. ## Проверка схем, аудит и сравнение редакций

### 11. P2. При выборе более узкого xsi:type применяется чужое ограничение атрибута

`xsd_bundle.py:267–283`, `xsd_validate.py:100–108`, `web/validation-worker.js:69–80`. В проверочном XML локальный `item` получил ограничение `fixed=false` одноимённой глобальной декларации. Первичная XSD приняла документ, дополнительная проверка Python его отклонила. Браузерный обработчик использует тот же порядок выбора правил. Такой отказ на текущих документах СФР не установлен.

В Python и WASM проверить один XML с локальной декларацией и контрольный вариант, где действительно применяется глобальный `fixed`.
