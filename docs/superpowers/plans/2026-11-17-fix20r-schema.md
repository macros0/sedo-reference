## 9 — Reject unknown or wrong-kind built-in components

`schema.py` now recognizes the XSD 1.0 built-in simple type names and `anyType` as the built-in complex type. Resolving an element/attribute/group ref against an XSD type name raises a descriptive ValueError, as does `xs:strng`. Attribute types and simple type restrictions require simple types; complex-content derivations require complex types; union member references require simple types. Reachable components are checked during normal field generation. `fields.build` already converts ValueError into a review status and `update_catalog` rejects the candidate, so no parallel publication-only validator was introduced.

Regression: `tests.test_schema_content.SchemaContentTests.test_unknown_or_wrong_kind_builtin_components_are_rejected`. The first succeeds, the second reports the failed type and preserves the byte-exact catalog and complete field directory from the previous release.

## 11 — Preserve exact fetched import edges

When existing archive layout and then URL-relative layout cannot resolve a WSDL closure uniquely, `_relative_archive` now retains each fetched source edge's exact URL target in a versioned ZIP comment (`SEDO-XSD-imports-1`). Original member bytes and their names remain intact; no source XSD is rewritten. Existing unambiguous archives keep their prior bytes and have no new comment. The map is used before filename fallback, with namespace checks. Missing explicit targets fail closed.

`SchemaFiles` carries the selected edge map into bundle preparation; its temporary analysis archives retain the map too. Dependency metadata exposes `import_targets` per source. `bridge` prefixes both sides of these exact edges and restores the same map in combined DOCX/WSDL archives. Rewritten working copies use the verified target while `originals/` retains source bytes.

Red: the changed existing WSDL regression failed for all absolute, root-relative and mixed modes with `Неоднозначный импорт ... Common.xsd`. Green: `test_exact_absolute_and_root_relative_includes_preserve_fetched_edges` checks both differing Common.xsd files, real flattened enum types, exact offline manifest replay and native bundle preparation. `test_exact_import_targets_survive_document_bridge` verifies child v1 keeps its actual v1 enum after bridge/bundle selection. `test_missing_exact_target_cannot_fall_back_to_another_common_schema` removes a recorded target and verifies refusal.

The ZIP comment's 65,535-byte format limit is checked explicitly; an excessively large exact edge map fails with a diagnostic instead of being truncated. This does not affect existing archives or the tested bounded closures.
