# Веб-исправления № 1, 11–14

16 ноября 2026 года. Изменения наложены на существующий грязный кандидат; сайт и данные в рамках этой части не пересобирались, коммит не создавался.

## Решения

- **№ 1 и 14.** Проверка поиска 32210 получает контролируемые названия, текущие и архивные редакции обоих контуров через подмену каталога. Ожидания больше не запрещают официальному продуктивному названию содержать слова «заработной плате». Заголовок карточки и страницы сообщения выбирается из текущей редакции выбранного контура, затем из текущего перечня, затем из истории. Архивные названия остаются доступны поиску. Chromium проверяет новое название, поиск по ID и архивному названию, обе сохранённые редакции и независимость контуров.
- **№ 11.** Перед сравнением собираются все подтверждённые пары путей. Для каждой пары родителей сопоставляются непосредственные дети: явные однозначные пары имеют приоритет над совпадением имени. Переименование нормализуется только для проверки эквивалентности; показанные значения сохраняют исходные имена. Это работает для обычной и ограниченной модели содержимого, вложенных групп и переименованного корня. `all` и `choice` сохраняют независимость от порядка после нормализации. Разделение/объединение отмечается отдельным свойством «Порядок дочерних элементов требует проверки» с конкретными неоднозначными путями. Изменение порядка попадает в обычный счётчик и лист Excel «Изменения».
- **№ 12.** Формула использует `MATCH(TRUE,INDEX(EXACT(ячейка,диапазон),0),0)` и `IFERROR`. `EXACT` различает регистр и сравнивает `*`, `?`, `~` буквально; дополнительное экранирование не требуется. Обёртка `INDEX` предназначена для обычного ввода формулы в старых Excel без динамических массивов/CSE. Новые функции с `_xlfn` не используются. В XLSX после записи/чтения проверены формулы, разные описания путей `processNum`/`processnum`, буквальная звёздочка, успешный импорт точных путей и отказ импорта `processNUM`.
- **№ 13.** Общая сортировка сначала сравнивает даты, при совпадении (включая две неизвестные даты) предпочитает текущую публикацию архивной, затем использует ID редакции для стабильности. Одна сортировка обслуживает карточки, переход между типами и начальные стороны сравнения. Проверены оба порядка входных данных и оба взаимных порядка ID текущей/архивной редакции.

Новая видимость перестановки обнаруживает реальное изменение порядка `registryNum`/`batchNo` относительно `responseInfo` в 105 → 10510. Поэтому связанный тест применения сопоставлений теперь ожидает при поиске `socialAssistNum` две карточки (родителя и ребёнка), а отменяет явно выбранное дочернее соответствие.

## Проверки

До изменения реализации три профильных Node-набора дали ожидаемый RED: пропущенный родитель при перестановке сопоставленных детей; архивная редакция при равной дате; прежняя нечувствительная к регистру формула. Два новых Chromium-сценария отдельно запущены с исходными архивными `web/*.js` в изолированной временной папке: ожидаемо показаны старый заголовок и архивный ID. Рабочие исходники для этой проверки не менялись.

После исправлений:

- `node tests/test_compare.cjs`, `node tests/test_cross_message_compare.cjs`, `node tests/test_comparison_export.cjs`, `node tests/test_comparison_mapping.cjs` — GREEN.
- `node tests/test_mapping_apply.cjs` после согласования поиска с новым изменением родителя — GREEN.
- `playwright test tests/browser/review-regressions.spec.cjs --reporter=line --output fix15-web-results.tmp` с установленным Playwright из существующего worktree и маршрутизацией на исходники `web/` — **8/8 GREEN**, 9,2 с. Набор включает прежние проверки прямых ссылок, поиска, модулей и ограничений.
- Общий запуск всех 27 Node-наборов: первоначально 25/27; отказ `test_mapping_apply.cjs` исправлен и повторно проверен. Второй отказ передан владельцу Python-части: `test_attribute_ref_constraints.cjs` → `schema.py:check_substitution_rules` → `self.context[node]` выдавал `KeyError` для временного элемента из `xsd_bundle._attribute_checks`. Он не относится к веб-изменениям. Общую проверку готового кандидата выполняет основной агент.

В Node.js 26 остаётся предупреждение среды об отсутствии `--localstorage-file`; проверки проходят. Обычный запуск Playwright внутри sandbox зависал при создании локального сервера; успешные проверки выполнены с разрешённым запуском вне sandbox.

**Ограничение № 12:** Microsoft Excel в этой системе не зарегистрирован как COM-приложение. Пересчёт в настольном Excel не выполнен; ExcelJS сохраняет и читает формулы/кэш, но не вычисляет их. Проверки XLSX и импортёра не выдаются за проверку реального пересчёта.

## Сохранность рабочей копии

Первый запуск Playwright ошибочно использовал штатный `test-results` и удалил хранившийся там baseline ZIP и прежние результаты тестов. Основной агент уведомлён сразу; изменённые тесты восстановлены обратной дельтой в `fix15-original-web.tmp`, их SHA совпали с исходным манифестом. Основной агент восстановил общий baseline в `fix15-baseline-restored.tmp`. Все последующие результаты этой части находятся в игнорируемых каталогах `*.tmp`; удалённые прежние диагностические результаты не восстановлены. Изменения исходников пользователя сохранены.
