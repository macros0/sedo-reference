# Ежедневный сбор WSDL/XSD через SourceCraft

[SourceCraft](https://sourcecraft.dev/alexey-sagitov/sedo-xsd-collector) запускает
`sfr-daily` в **07:00 по Москве** (`0 4 * * *`, UTC). Продуктивный и тестовый контуры
собираются последовательно. GitHub запускает Check SFR catalogs в **07:17 по Москве**:
`python sourcecraft_pull.py` получает снимки перед существующим импортом документов.
Возможны обычные задержки запуска CI; обе задачи доступны также для ручного запуска.

## Паузы и сбои

Один запрос одновременно; минимум 5 секунд после окончания предыдущего; таймаут
30 секунд; одна попытка. После первой ошибки (включая 403, 429, 503 и таймаут)
новых запросов нет, в том числе по альтернативным адресам и следующему контуру.
`Retry-After` сохраняется в отчёте. Бюджет сборщика — 32 запроса, CI — 10 минут.
Это консервативные настройки проекта, а не официальный разрешённый лимит СФР.

В существующем импорте DOCX/ZIP GitHub включает `SEDO_SFR_POLITE=1`: все рабочие потоки
используют одну очередь с теми же паузами и остановкой при первой ошибке; бюджет
каталога — 1000 запросов. Отдельная живая проверка WSDL перед Pages убрана.

Если любой контур не собран полностью, новая публикация SourceCraft не создаётся.
Старые успешные данные остаются доступны. Ошибка чтения или проверки входов в GitHub
останавливает обновление, опубликованный справочник сохраняется. Проверка HTTPS включена.

## Хранение и получение

Ветка `main` SourceCraft содержит код и cron. Отдельная ветка `snapshots` содержит:

- `objects/<SHA-256>` — исходные WSDL/XSD и архивы;
- `collector/<prod|test>/<content_id>.json` — неизменяемые манифесты;
- `index.json` — всю историю и указатели текущих наборов.

Новые наборы добавляются, старые не удаляются. Неизменный набор не создаёт коммит.
При возврате к прежнему содержимому меняется только указатель текущего набора;
первый манифест и его дата сохраняются. Публикация только fast-forward; конфликт
публикации завершается ошибкой, без force push. Push в snapshots не запускает новый сбор.

GitHub фиксирует commit SHA ветки snapshots, читает публичные RAW-файлы этого коммита,
скачивает только отсутствующие манифесты и объекты, проверяет SHA-256, content_id,
контур, размеры и полное замыкание импортов офлайн. Повреждённая пачка отклоняется до
записи. `state/collector/feed.json` определяет текущий набор, включая возврат к старому.
История редакций, исходные DOCX и прежние деревья сохраняются существующим механизмом.

GitHub-токен в SourceCraft не нужен. Запись своей ветки использует временный
`SOURCECRAFT_TOKEN` из CI; токен передаётся Git через окружение и не пишется в файлы
и журналы. Публичное чтение GitHub не требует SourceCraft-токена.

## Проверка и восстановление

Ручной запуск: SourceCraft CI/CD → sfr-daily на main, затем GitHub Actions →
Check SFR catalogs → Run workflow. Отчёт SourceCraft: артефакт `results/daily-report.json`.
Отчёт получения GitHub: `sourcecraft-report.json` в артефакте `sfr-update-report`.
Результат публикации проверяется в Publish reference. Не запускайте несколько сборов одновременно.

Общие модули collector.py, collector_snapshots.py, collector_feed.py,
collector_transport.py, sync.py, wsdl_sources.py и публичные certs/ обновляйте
согласованно с основным проектом. Пользовательские XML и токены не добавляются.

После проверки новой цепочки домашний sedo-collector.timer выключается, чтобы не
дублировать обращения. Код и архивы домашнего сборщика остаются для восстановления
по [прежней инструкции](russian-collector.md). Перед его включением остановите
расписание SourceCraft, чтобы два сборщика не обращались к СФР одновременно.
